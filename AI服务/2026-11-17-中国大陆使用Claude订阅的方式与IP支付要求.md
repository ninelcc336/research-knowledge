# 中国大陆使用 Claude 订阅的方式与 IP、支付要求

调研日期：2026-11-17。核查范围：个人订阅的地区资格、网络与 IP、网页及手机支付、礼品订阅、第三方代充与合租，以及 Claude Code/API 的区别。

本次更新（同日）：新增独立专题[Claude Code 订阅固定出口 VPS 选型](./2026-11-18-Claude-Code订阅固定出口VPS选型.md)，核查本地运行、VPS 只作出口时的 DMIT、LisaHost 和搬瓦工候选、近期反馈及套餐条件；本篇保留地区资格和支付范围。

本次直接读取 Anthropic、Apple、Google 的当前官方页面，并对照近期中文教程。没有登录用户账户、购买网络服务、注册账户或实际扣款；文中的“官方确认”表示入口或规则得到确认，不表示已在大陆完成购买和续费实测。旧发布日期的官方文件只在今天仍公开有效时作为现行规则引用，搜索摘要和文章标题中的“最新”“亲测”不作为成功证据。

## 1. 结论与方案选择

**人在中国大陆，目前没有官方支持的 Claude 个人订阅使用方案。** Anthropic 于 **2026-11-12** 生效的《Supported Regions Policy》明确将“人在不支持地区时使用”列为不支持情形，范围包括 Claude.ai、Claude Code、Cowork、API，以及云平台和授权转售渠道。大陆、香港、澳门均未列入清单；台湾、日本、新加坡、美国等在清单内。[S1][S2]

现实中讨论的方案主要是在解决访问和付款。**境外出口 IP、境外银行卡、美区 Apple 账户，都不会单独改变实际所在地这一要求。** 付费账户也可能被要求再次验证支付方式或身份；官方没有给出“某种 IP 或卡保证长期可用”的承诺。[S1][S6][S13][S14]

| 方案 | 需要准备什么 | 当前核查结论 | 对大陆使用解决了什么 |
| --- | --- | --- | --- |
| 网页直接订阅 | 可正常访问的网络、自有 Claude 账户、符合支持地区要求的信用卡/借记卡和真实账单资料；必要时完成 3DS | **官方现行入口**；不接受官网 PayPal 直付 | 可解决支付，但不改变大陆地区限制 |
| iPhone/iPad 内购 | 支持的设备和系统、可取得官方 App 的商店地区、Claude 账户、Apple 接受的付款方式或可用余额 | **官方现行入口**；Apple 余额可用于 App 订阅，具体订单可能仍要求卡 | 可避免直接把银行卡交给 Anthropic；不改变 Claude 地区限制 |
| Android 内购 | 官方 Claude App、可用 Google Play、正确的 Play 地区/支付资料、当地支持的付款方式 | **官方现行入口**；换区与礼品卡有所在地要求 | 将支付交给 Google；不改变 Claude 地区限制 |
| Claude 官方礼品订阅/兑换码 | 过去已购买的有效礼品 | **官方已暂停新购，未公布恢复时间**；旧礼品仍有兑换规则 | 不能作为现在持续购入、续费的可靠入口 |
| 第三方代付、虚拟卡 | 具体卡商/代付商、真实资金和账单来源、官方账户 | **未验证任何商家当前对大陆新客的开通及续费成功率** | 可能代解决付款；不解决账户所在地和验证 |
| 成品号、共享号、合租 | 卖家提供的账号或转发平台 | 共享个人账户与官方条款冲突；无法据广告确认独享额度或账户归属 | 不能等同于本人持有的官方订阅 |
| 境外远程电脑、VPS 或代理 | 境外设备/网络及持续费用，另有账户和支付条件 | 能改变请求出口或运行位置；没有证据证明可豁免实际使用者所在地要求 | 只改变网络路径，不能据此宣称受官方支持 |

**选择建议：** 若已经符合官方地区资格，有合适境外卡时优先网页月付；没有卡但已有符合条件的 iPhone/iPad 与 Apple 账户时，可研究 iOS 内购。Android 更适合原本就有正常 Play 地区和支付资料的人。若长期实际在大陆，应先接受“官方不支持、无已验证长期方案”的结论，再衡量技术可用性；不应先为“包稳定”的 IP、年费或代充付款。

**新账户还需要手机号条件。** 官方当前要求新用户验证支持地区可接收短信的号码，不接受 VoIP、Google Voice、App 生成号码或固话，并建议使用长期持有的号码；一个号码最多验证三个账户。消费者条款要求年满 18 岁或所在地更高的最低同意年龄。只有邮箱、境外出口和付款方式，仍不构成完整的开户条件。部分场景还可能要求政府照片证件及现场自拍，但本次没有证据表明每位付费用户必定遇到身份核验。[S6][S13][S14]

## 2. IP：要核实哪些条件

### 2.1 出口地区与实际所在地是两件事

官方订阅说明直接写明：付费计划仅向**实际位于支持地区**的用户提供。不是简单要求 IP 显示美国，也不是只有美国能用。[S3]

- **大陆出口：** 大陆不在支持地区清单内，不能把能偶尔打开网页当作地区已开放。
- **香港/澳门出口：** 两地也未列入当前清单，“换香港节点就解决”没有官方依据。
- **日本、新加坡、台湾、美国等出口：** 这些地区在支持清单里，但出口地址本身不能证明使用者实际位于当地。
- **境外手机漫游、境外 SIM：** 号码所属地、IP 出口和使用者实际位置应分别判断；不能只看其中一个。
- **境外远程桌面/VPS：** 人仍在大陆远程使用，不能仅凭设备在境外就认定满足实际所在地要求。[S1][S3]

政策还限制在不支持地区注册、设总部或被当地人员/实体多数持有或控制的组织及其人员。因此“先注册一家境外公司”“用海外团队席位”也不能自动解决资格问题。政策没有把“中国国籍”直接列成个人禁用条件，不应把所在地限制写成国籍限制。[S1]

### 2.2 住宅、原生、静态、机房 IP 的证据边界

| 常见说法 | 本次能够确认的程度 | 实际判断方法 |
| --- | --- | --- |
| 必须住宅 IP | 在本次核查的官方地区、订阅及登录排障文件中未发现此要求 | 不以“住宅”标签代替地区资格和实际可访问性 |
| 原生 IP 保证不封 | 未找到官方承诺；第三方对“原生”的定义也不能充当资格证明 | 不能据商家标签推导账户稳定率 |
| 静态、独享一定更安全 | 固定地址可以减少出口变化，这是网络属性；没有可靠数据证明其 Claude 封禁率 | 需评估实际地址、服务连续性和价格，不把固定地址当免责条件 |
| 机房 IP 一律不能用 | 未找到官方一刀切规则 | 不能把单次通过或失败推广到整个 IP 类型 |
| 浏览器能用，Claude Code 就能用 | 不能成立；各程序可能使用不同网络配置 | 分别确认网页登录、App、CLI 的连接是否正常 |
| 付费后就不再检查网络/账户 | 不成立；官方有登录排障、支付复核和身份验证流程 | 扣款成功只说明该次支付完成 |

官方登录错误排障甚至建议先**停用 VPN**、禁用扩展、清理缓存，再查看服务状态。因此无法从官方资料推出“购买某类代理就是官方解决办法”。这些建议适用于有使用资格者排障，并不表示大陆停用代理后就获得服务资格。[S15]

本次未对具体网络供应商做多日、多地区或续费实测，不能给出“某服务成功率 99%”“某 IP 风险分低于多少就能用”的排名。用户后续已明确采用本地 Claude Code、VPS 固定出口场景，具体候选与证据见[固定出口 VPS 专项](./2026-11-18-Claude-Code订阅固定出口VPS选型.md)；专项同样没有将社区反馈冒充长期实测。

## 3. 三种现行官方支付入口

### 3.1 网页：支持地区发行及账单条件是关键，卡面标识不够

官方说明网页订阅只接受**信用卡和借记卡**；拒付排查要求付款方式的账单地址与来源国家/地区属于支持范围，且地址与银行留存信息一致。必要时还要完成 3DS 验证、确保余额充足，并由发卡行允许交易。[S4][S5]

因此：

1. 大陆银行发行的 Visa/Mastercard，不能仅凭支持外币消费就视为符合 Claude 的账单地区要求。
2. 香港卡也不能因为是境外卡就默认可用；香港未列入当前支持地区清单。
3. 卡片发行及账单条件符合要求，仍不等于人在大陆满足订阅所在地条件。
4. 使用银行真实留存地址，不以网上生成的美国地址替代；官方指出很小的地址差异也可能导致拒付。
5. 官网不接受 PayPal、Venmo 这类第三方支付处理方式；也没有为个人网页订阅列出支付宝或微信直付入口。[S4][S5]

**虚拟卡与实体卡的区别不应被夸大。** 本次官方资料没有提供“全部虚拟卡禁用”或“某卡段必过”的清单。应核查具体发行地区、账单地址、是否支持循环扣款和 3DS，以及大陆个人今天能否开户；不能照搬旧卡商教程。本次没有验证出可直接推荐的卡商，亦未据旧资料宣称 WildCard、Depay 等某个具体产品当前一定能用或已关闭。

### 3.2 iOS：Apple 内购与余额路径，确实有依据

Anthropic 官方确认：在 Claude iOS App 的设置中选择“Upgrade to Pro”，按提示完成 App 内购买。官方安装指南指向 **Claude by Anthropic**，当前要求 iOS/iPadOS **18.0 或更高**；不支持地区可能找不到 App。[S7][S8]

Apple 官方确认账户余额可购买 App 内项目及 App 订阅，但同时提醒某些购买仍需要留存信用卡、部分订阅不能使用余额。因此“只要充礼品卡，就永远不需要绑卡”不是官方保证。[S9]

这条路径的准备顺序是：

1. 确认使用资格及目标商店能取得官方 App。
2. 确认 Apple 账户地区和实际账户条件；若要换区，先处理余额、未结束订阅、退款/预购及家人共享，可能需新地区有效付款方式。[S10]
3. 使用该地区合法取得且可兑换的余额或付款方式；例如美国礼品卡只能关联美国账户，并用于美国购买，不是全球通用余额。[S11]
4. 登录**本人要长期使用的 Claude 账户**，在官方 App 查看当前可购套餐、含税总价及实际付款选项，再确认购买。
5. 订阅和取消由 Apple 管理；Apple 订单退款需向 Apple 申请。之后使用 Claude 仍受 Anthropic 的地区及账户要求约束。[S5][S18]

近期 AISubDeal 页面自称于 **2026-11-16** 观测到美区 Pro 月付税前 $20，但该页也明确“尚未附本站实测截图”，部分来源核对日期仍在 10 月。本次读取 App Store 产品 URL 未取得可核验的 Claude 内购价格表，所以**不把第三方观测价当成本次独立验证的商店价格**，尤其不沿用其中 Max 5x/20x 的旧商品命名。[T1]

支付宝/微信买 Apple 礼品卡，与 Claude 官网接受支付宝/微信是不同交易；前者还要承担卖家货源、兑换地区和退款条件，不能把卖家收款截图当作 Claude 官方授权证明。

### 3.3 Android：可内购，但不是“买张 Google 礼品卡就行”

Anthropic 官方提供 Android App 内“Upgrade to Pro”入口，支付交由 Google Play。[S5][S12]

Google 当前换区说明要求：设置新国家/地区时，必须身处当地并持有当地付款方式；首次设置国家及之后换区通常至少间隔 **90 天**，还可能有其他限制，家人群组成员不能直接换区。不能沿用所有旧教程中的“一年只能换一次”作为今天的通用规则。[S16]

Google 礼品卡只能在购买时所属国家/地区及币种内兑换、使用，账户地区也必须匹配。官方页还列明：新加坡的礼品卡及由礼品卡充值的余额已于 **2025-02-01** 失效，马来西亚的礼品卡和预付余额于 **2026-02-01** 失效。因此“新加坡节点＋新加坡 Google 礼品卡”之类旧教程不能照用。[S17]

对原本没有可用 Play 商店地区及当地付款方式的人，这条路径的准备条件通常多于已经具备 Apple 账户条件的 iOS 内购。Google 在某地区接受 PayPal 等方式，也不代表 Claude **网页**接受同样付款方式。

## 4. 第三方代付、激活码、成品号如何判断

### 4.1 官方 Claude 礼品和 Apple 礼品卡必须分开

**Claude 官方礼品订阅目前对所有账户暂停新购，官方未公布恢复日期。** 过去购买的礼品仍有网页兑换入口，接收人兑换时不需要信用卡；有 iOS/Android 有效订阅的人需先等移动订阅结束。[S19][S20]

因此，卖家声称“今天仍可持续新买官方礼品码”时，必须解释来源与官方暂停公告的关系。能打开 `claude.ai/gift/redeem`，只能证明兑换入口存在，不能证明新购已恢复。Apple 礼品卡是 Apple 余额商品，不受 Claude 礼品订阅暂停新购这一条直接影响，但受 Apple 自己的使用条件约束。

### 4.2 代付没有消除地区与账户问题

- **本人账户代付：** 可能确实支付到本人账户，但应确认订单商户、订阅套餐、付款来源、下次扣款主体与退款路径。本次未验证具体商家的到账和续费。
- **虚拟卡自付：** 是银行卡路径的一个变体，不是新的地区资格。额外成本可能包含开户、充值、汇兑、交易和续费费用。
- **“免密码”激活：** 若要求提供 Cookie、会话令牌、refresh token 或登录链接，仍涉及账户访问能力，不能因为没要密码就认定没有交出凭据。
- **个人号合租/共享：** 官方消费者条款禁止分享登录资料或把账户提供给别人，不适合当作本人稳定持有的订阅。[S6]
- **Team 席位：** 正规组织席位与共享一个个人号不同，但购买席位不豁免地区政策；个人网页 Pro/Max/Ultra 与组织席位的权益和管理权也不相同。[S1][S18]
- **镜像站/API 中转：** 是另一个服务商的交付，通常不在本人 Claude 账单中形成个人订阅；不能仅凭标注“Claude Pro/Max”就认为包含官方 Projects、Claude Code 登录及全部订阅权益。

没有完成当前商家验证前，不列“推荐代充名单”或人民币报价。低价、补号和“包封赔”均不能证明服务可以持续，商家的退款承诺也不等于 Anthropic 的退款承诺。

## 5. 当前套餐、Claude Code 与 API：几条容易过时的信息

**2026-11-17 官网定价快照**如下，均为网页美元价格，未含适用税费；手机平台和地区价格以实际订单为准。[S18][S21]

| 套餐 | 当前网页价格 | 与本题有关的区别 |
| --- | --- | --- |
| Pro | $20/月；年付 $200，官网约写 $17/月 | 含 Claude Code；不含普通 Console API 使用额度 |
| Max | $100/月 | 5 小时及每周用量为 Pro 的 5 倍；可按规则领取每月 $100 API credits |
| Ultra | $200/月 | 每周用量为 Pro 的 10 倍；已验证账户无 5 小时限制；可按规则领取每月 $200 API credits |

**不要继续照抄“Max 5x / Max 20x”作为当前官网完整套餐结构。** 今天官网已经列为 Pro / Max / Ultra。App Store 第三方价格页或旧商品名称可能仍有旧措辞，不能据此覆盖官网当前套餐说明。[S18][S21][T1][T2]

同样不能再笼统说“所有 Claude 订阅与 API 额度完全无关”：当前 Max、Ultra、Team 已有月度 API credits，但需有效订阅满 7 天、关联一个 Console 组织后领取，按周期过期且不结转；Pro 不符合资格。API credits 与 Claude/Claude Code 的订阅用量仍是分开的，不能直接抵交互式 Claude Code 或订阅超额使用。[S22]

若目的就是 Claude Code，Pro 已有官方订阅登录路径；不必只因需要写代码就买 $100/$200 档。通过其他 API 服务接入编程客户端，是另一种采购方式，不能冒称已经购买了 Claude 个人订阅。经云平台或授权转售商获得 Claude 模型也仍在当前地区政策范围内，不能把 Bedrock/Vertex 等直接列为大陆的官方豁免路径。[S1][S18]

## 6. 近期教程中已发现的错误与尚未确认事项

| 资料/说法 | 当前发现 | 对决策的影响 |
| --- | --- | --- |
| 卡码笔记充值文，自称 2026-11-03 更新、全部亲测 | 写官网支持 PayPal，与官方仅银行卡相冲突；仍列 Max 20x；还把境外卡描述为不会风控、续费不会出问题 | 不采纳其支付成功率及“最稳”结论；新日期不能替代内容核查。[T2][S4][S18] |
| AISubDeal 订阅文，写有 2026-11-16 价格观测 | 披露未附实测截图，来源日期混合；移动 Max 商品名与当前官网不一致 | 仅作为近期实践路线线索，价格和开通成功不记为本次实测。[T1] |
| “美国原生住宅 IP＋卡＝永久稳定” | 官方没有公开对应保证；现行政策要求实际所在地 | 不给出成功率，不推荐先付高额网络年费。[S1][S15] |
| “官方 Claude 礼品码仍可随时新买” | 官方新购暂停，未公布恢复时间 | 旧码兑换与新码供应必须区分。[S19][S20] |

尚未确认：具体卡商对大陆个人的新开户条件与当前可用卡段；特定 IP 服务的长期通过率；个人账号的现有验证状态；商店结账时某个账户能否仅用余额完成购买；第三方卖家的真实资金来源和续费表现。

若要把本调研继续落实到某个具体人，最少需要设备类型、是否已有本人 Claude 账户、是否有支持地区的银行卡/Apple/Google 支付资料，以及是否实际位于支持地区。没有这些条件，不能负责任地指定一套“照做就成功”的步骤。
