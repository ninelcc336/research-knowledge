# Agent 项目级记忆方案调研

> 调研日期：2026-08-20。本文以 Codex/ChatGPT、Claude Code、Pi、OpenCode 和 WorkBuddy（腾讯云代码助手 CodeBuddy）的当前官方文档、官方仓库说明为主要依据。产品能力和文件路径可能随版本变化，落地前应再核对目标版本。

## 结论

Agent 的“项目级记忆”不应只理解为模型自动记住了什么，而应拆成四层：

1. **项目规则**：团队明确写入仓库、可审查和可回滚的约束，例如构建命令、目录约定、编码规范和安全边界。
2. **项目知识**：架构说明、决策记录、运行手册和领域词汇等较长资料，通常按需读取，不应全部塞进每次会话。
3. **自动记忆**：Agent 根据对话自动提取的个人或本机状态，适合保存偏好、调试经验和重复性背景，不适合作为团队规范的唯一来源。
4. **会话状态**：聊天记录、分支、压缩摘要和任务进度，用于继续某一次工作，不等于稳定的项目知识。

对于多 Agent 共用的代码仓库，推荐采用以下主方案：

- 以根目录 `AGENTS.md` 作为跨 Agent 的共享项目入口，只保存稳定、短小、可验证的规则。
- 用 `docs/architecture.md`、`docs/decisions/`、运行手册等普通 Markdown 保存较长的项目知识，并在 `AGENTS.md` 中说明何时读取。
- Claude Code 通过一个很薄的 `CLAUDE.md` 导入 `AGENTS.md`，不要维护两份完整规则；WorkBuddy 若没有 `CODEBUDDY.md`，可直接兼容根目录 `AGENTS.md`。
- Agent 自动生成的记忆留在用户目录或项目本地忽略文件中，不提交到 Git；需要团队共享的结论必须回写到规则或项目文档，并经过代码审查。
- 对必须执行的动作使用 Hook、CI、权限策略或脚本，不要把“模型应该记住”当作强制执行机制。

## 评估边界

| 层次 | 典型载体 | 是否应提交 | 主要作用 | 主要风险 |
|---|---|---:|---|---|
| 项目规则 | `AGENTS.md`、`CLAUDE.md`、`CODEBUDDY.md`、Rules | 是 | 让新会话遵守团队约定 | 文件过长、规则冲突、只靠提示词而未被工具强制 |
| 项目知识 | 架构文档、ADR、运行手册、领域词汇 | 是 | 保存可复用事实和决策依据 | 过期、入口不清、每次全量加载浪费上下文 |
| 自动记忆 | `~/.codex/memories/`、Claude `MEMORY.md` 等 | 否 | 记住个人偏好和工作经验 | 误记、过期、不可见于团队、可能带入不应共享的信息 |
| 会话状态 | JSONL 会话、聊天记录、压缩摘要 | 通常否 | 继续某次任务或分支 | 只能说明过去发生过什么，不能替代当前仓库事实 |
| 能力扩展 | Skills、命令、MCP、插件 | 视情况 | 提供流程、工具和外部上下文 | 权限扩大、远程内容漂移、第三方代码风险 |

比较各 Agent 时，重点看六个问题：

- **共享性**：项目规则是否能随 Git 进入代码评审，自动记忆是否只在本机有效。
- **作用域**：是否支持全局、项目、子目录和个人覆盖，覆盖顺序是否可预测。
- **加载方式**：启动时全量加载、按路径加载，还是只加载名称后按需展开；有没有大小上限。
- **自动化程度**：是否会自动写入和检索记忆，能否查看、修改、删除或关闭。
- **兼容性**：能否复用 `AGENTS.md`、`CLAUDE.md` 或 Agent Skills，迁移时是否需要复制内容。
- **强制性与审计**：规则只是提示词，还是能由 Hook、权限系统和 CI 形成确定性约束。

## 1. Codex / ChatGPT

### 1.1 两个需要区分的项目概念

ChatGPT 的 Project 是产品层的工作空间：可以把相关聊天、文件、项目说明和连接的来源放在一起，在后续聊天中复用。ChatGPT 网页端的 Project 不直接访问本机文件夹，需要上传或连接来源；ChatGPT 桌面端还支持把本地文件夹作为 local project 交给 Codex 使用。

Codex CLI 和 IDE 扩展的“项目”更接近工作目录：CLI 从启动目录或 `--cd` 指定目录读取文件，IDE 扩展使用打开的文件夹或 workspace。项目组织、聊天记录和本地仓库指导是不同层次，不能因为聊天属于同一个 Project 就认为仓库里的 Agent 规则已被所有客户端加载。

### 1.2 共享项目规则：`AGENTS.md`

Codex 在开始工作前建立 instruction chain。其主要规则是：

- 全局位置默认是 `~/.codex/AGENTS.md`；同级存在 `AGENTS.override.md` 时优先使用 override。
- 从项目根目录向当前工作目录逐级查找；每一级在 `AGENTS.override.md`、`AGENTS.md` 及配置的 fallback 文件名中最多选一个。
- 文件按从根到当前目录的顺序拼接，靠近当前目录的内容排在后面，因此可以提供更具体的目录级规则。
- 默认有 `project_doc_max_bytes` 限制，官方当前文档说明默认值为 32 KiB；内容过大时应拆分到更近的目录或提高配置，而不是无限扩展根文件。
- `AGENTS.md` 会随仓库提交，适合放构建与测试命令、代码审查要求、目录约定、架构边界和常见陷阱。

这是一套**项目指导机制**，不是“Agent 自主学习后的项目数据库”。官方建议把必须持续生效的团队指导放在 `AGENTS.md` 或已提交文档中，把 memories 视作辅助回忆层。

### 1.3 自动记忆：Codex 本地 memories

Codex/ChatGPT 文档把 ChatGPT web memory 和本地 Codex memory 分开：

- 本地 Codex memories 默认关闭，可在 ChatGPT 桌面端设置中启用，或在 `config.toml` 中打开 `features.memories`。
- 记忆存放在 `CODEX_HOME` 下，默认目录为 `~/.codex/memories/`，包含摘要、持久条目、近期输入和支持证据等生成状态。
- Codex 可以在后台从符合条件的旧聊天提取记忆；对当前聊天是否使用记忆、是否贡献给未来记忆，可以用 `/memories` 控制。
- 文档说明 Codex 会尝试对生成的记忆字段脱敏，但仍应在分享或迁移 Codex home 前检查本地记忆。
- 外部上下文、速率限制、会话是否活跃等配置会影响记忆是否生成；因此它不是每个会话结束都必然产生的同步日志。

本地 memories 适合个人偏好、重复性工作习惯和非规范性经验，不应承载“所有成员必须遵守”的规则，也不应作为跨机器、跨账号或 CI 运行的项目事实来源。

### 1.4 适用判断

Codex 的强项是把仓库级指导、目录级覆盖和 ChatGPT Project/本地工作区组织组合起来。推荐把 `AGENTS.md` 作为跨 Agent 规范，把 ChatGPT Project instructions 用于产品层的研究目标、输出格式或共享来源；两者都不要代替仓库中的架构和安全文档。

## 2. Claude Code

### 2.1 `CLAUDE.md` 规则层

Claude Code 的项目入口是 `./CLAUDE.md` 或 `./.claude/CLAUDE.md`。它还支持：

- `~/.claude/CLAUDE.md`：所有项目的个人说明。
- 组织托管的 `CLAUDE.md`：由 IT/DevOps 管理的组织级政策。
- `./CLAUDE.local.md`：当前项目的个人偏好，适合放入 `.gitignore`。
- 当前目录及祖先目录中的 `CLAUDE.md` 和 `CLAUDE.local.md`：从上到下拼接；子目录中的文件在 Agent 读取该目录文件时按需加入。
- `.claude/rules/`：将测试、前端、安全等规则拆成多个文件，可用 `paths` frontmatter 限定匹配的文件类型或目录。
- `@path/to/file` 导入：将其他文件在启动时展开，官方当前文档说明递归导入最多四层。

Claude Code 把 `CLAUDE.md` 当作上下文而非硬性配置；要无论模型如何判断都阻止某个动作，应使用 `PreToolUse` Hook、权限规则或 CI。

### 2.2 与 `AGENTS.md` 的兼容方式

Claude Code 原生读取 `CLAUDE.md`，不自动把 `AGENTS.md` 当成同名规则文件。官方给出的共存方式是新建一个很薄的 `CLAUDE.md`：

```markdown
@AGENTS.md

## Claude Code 专属约定

- 仅在 Claude Code 中适用的工作流写在这里。
```

也可以用符号链接，但 Windows 创建符号链接可能需要管理员权限或开发者模式；在 Windows 团队中，使用 `@AGENTS.md` 导入更容易推广。关键是只保留一份共享规则，避免 `AGENTS.md` 和 `CLAUDE.md` 长期分叉。

### 2.3 Auto memory

Claude Code 的 Auto memory 与 `CLAUDE.md` 是两套互补机制：前者由 Claude 写入学习结果，后者由人维护规则。官方文档当前说明：

- Auto memory 默认开启，可通过 `/memory` 或设置项关闭，也支持环境变量禁用。
- 项目记忆位于 `~/.claude/projects/<project>/memory/`，同一 Git 仓库的 worktree 和子目录共享该目录，但记忆是机器本地的，不会随仓库或云环境同步。
- `MEMORY.md` 是索引，启动时最多加载前 200 行或 25KB，以先到者为准；`debugging.md`、`patterns.md` 等主题文件不会自动全量加载，需要按需读取。
- 记忆文件是普通 Markdown，可以用 `/memory` 查看、编辑或删除；过期条目应主动清理。
- 也支持为有持久记忆需求的子代理配置独立 memory 目录，这和主会话 Auto memory 分开。

因此 Claude Code 的项目级方案可以分成“提交的 `CLAUDE.md`/`.claude/rules/`”和“本机自动 `MEMORY.md`”两条线。前者适合团队协作，后者适合个人工作加速；不要把 Auto memory 直接当作团队知识库。

### 2.4 适用判断

Claude Code 的规则分层和路径匹配能力较完整，适合大型仓库和多团队 monorepo。若仓库已经采用 `AGENTS.md`，推荐 `AGENTS.md` 作为事实源，`CLAUDE.md` 只做导入和少量 Claude-specific 规则；对需要强制执行的规范，另配 Hook 或 CI。

## 3. Pi

> 本文所称 Pi 指 pi-mono 中的终端 coding agent。当前官方仓库入口已显示为 `earendil-works/pi`，历史资料和社区链接中仍常见 `badlogic/pi-mono` 名称。

### 3.1 上下文文件

Pi 的核心定位是可扩展、保持最小化的终端 coding harness。当前官方 README 和 quickstart 文档说明：

- 全局上下文文件是 `~/.pi/agent/AGENTS.md`。
- Pi 会从项目父目录到当前目录查找 `AGENTS.md` 或 `CLAUDE.md`；同一目录有 `AGENTS.override.md` 时，它替代该目录的 `AGENTS.md` 或 `CLAUDE.md`。
- 匹配到的上下文文件会拼接到启动上下文中；交互界面启动头会列出已加载的 AGENTS 文件。
- 修改后可以重启 Pi 或执行 `/reload`；也可以用 `--no-context-files` / `-nc` 关闭发现。

这使 Pi 可以直接复用跨 Agent 的 `AGENTS.md`，也能在没有单独适配文件的情况下读取 Claude Code 项目的 `CLAUDE.md`。从作用上看，它的项目记忆核心是“启动时加载的规则文件”，而不是一个独立的自动记忆服务。

### 3.2 会话、压缩和技能不是同一层记忆

- 会话默认保存为按工作目录组织的 JSONL 文件，位于 `~/.pi/agent/sessions/`；支持 `/resume`、`/tree`、`/fork` 和 `--no-session`。
- 上下文过长时，Pi 用 compaction 把较旧消息总结为会话条目；切换分支时也可以生成 branch summary。这些摘要保留某次工作的连续性，不应被误写成稳定的项目事实。
- 技能从 `~/.pi/agent/skills/`、`.pi/skills/`、`.agents/skills/` 和包中发现，并按需加载。Pi 的文档还说明可以通过 settings 复用 Claude Code 或 Codex 的技能目录。
- 项目设置、项目包和扩展受 project trust 控制；第三方 Pi package/extension 可能执行任意代码，安装前应审查来源和权限。

当前 Pi 官方核心文档列出了上下文文件、会话和扩展机制，但没有把“根据对话自动抽取项目记忆”列为内置能力。若团队需要自动记忆，应通过扩展或第三方包实现，并把最终确认过的内容回写到仓库文档；不要把某个包的行为当作 Pi 核心保证。

### 3.3 适用判断

Pi 适合采用简单、透明的项目级方案：根目录 `AGENTS.md` 保存共享规则，`.agents/skills/` 保存可审查的按需工作流，项目进度写入普通 Markdown 或会话文件。它的优点是跨 Agent 文件兼容和可扩展性，代价是自动记忆、子代理、MCP 等能力需要自行组合或安装包。

## 4. OpenCode

### 4.1 规则与 instructions

OpenCode 的官方 Rules 文档以 `AGENTS.md` 为项目规则入口，并支持：

- 从当前目录向 Git worktree 根目录遍历的项目级 `AGENTS.md`。
- 全局 `~/.config/opencode/AGENTS.md`。
- Claude Code 兼容回退：没有对应 `AGENTS.md` 时使用项目 `CLAUDE.md`，全局则使用 `~/.claude/CLAUDE.md`；可用环境变量关闭这类兼容。
- 项目初始化命令 `/init`：扫描仓库并创建或改进精简的 `AGENTS.md`，内容重点是构建、测试、架构和项目约定。

OpenCode 的规则优先级是局部文件优先于全局文件；同一目录如果同时存在 `AGENTS.md` 和 `CLAUDE.md`，使用 `AGENTS.md`。在此基础上，还可以在项目 `opencode.json` 的 `instructions` 字段中列出 `CONTRIBUTING.md`、文档路径、glob 文件或远程 URL，所有 instruction 会与 `AGENTS.md` 合并。

这套 `instructions` 机制适合把较长项目知识拆到独立文件并按路径加载，例如：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines.md",
    "packages/*/AGENTS.md"
  ]
}
```

远程 URL 方便复用组织规则，但会引入网络可用性、内容漂移和供应链审查问题；团队规范优先提交到仓库，远程 instructions 只用于经过版本和权限治理的共享来源。

### 4.2 Skills 和自动记忆边界

OpenCode 的 Skills 遵循 Agent Skills 结构，可放在 `.opencode/skills/`、`.claude/skills/` 或 `.agents/skills/`，只把名称和描述放入可用列表，正文由 Agent 按需加载。这适合流程性知识，不应把所有架构事实都写成 Skill。

OpenCode 当前官方核心文档没有把类似 Claude Code 或 WorkBuddy 的原生自动记忆抽取作为项目机制；官方生态页列出了 `opencode-supermemory` 等跨会话持久记忆方案，它们属于可选生态集成。采用这类插件时，应单独审查数据存储、检索范围、删除机制和网络边界，不能把插件行为当作 OpenCode 核心保证。

### 4.3 适用判断

OpenCode 适合以 `AGENTS.md` 做简洁入口、以 `opencode.json` 的 `instructions` 组织大型仓库知识、以 Skills 提供按需流程。它对 `AGENTS.md` 和 Claude 约定的兼容性较好，但自动记忆不是核心默认能力，项目知识仍应回到 Git 管理的文件。

## 5. WorkBuddy（CodeBuddy）

> 腾讯云官方文档的产品名称主要写作 CodeBuddy Code、CodeBuddy IDE 或 WorkBuddy。下文用“WorkBuddy”指用户所说的这套腾讯云 Agent/代码助手能力。

### 5.1 项目记忆文件与规则

当前官方 CLI Memory 文档把静态项目记忆和规则拆开：

- 项目记忆可放在根目录 `./CODEBUDDY.md` 或 `./.codebuddy/CODEBUDDY.md`，适合项目架构、团队约定、常用命令和工作流，并随 Git 与团队共享。
- `./CODEBUDDY.local.md` 是当前项目的个人记忆，适合本地 sandbox URL、测试数据等，不应提交。
- `.codebuddy/rules/` 用于拆分代码风格、测试、安全和前端等主题规则；IDE 文档支持 `Always`、`Agent Requested`、`Manual` 三种应用方式，分别对应始终注入、模型判断相关时加载和通过 `@` 手动调用。
- 用户级 `~/.codebuddy/CODEBUDDY.md` 和 `~/.codebuddy/rules/` 跨项目生效，适合个人偏好和个人工作流，不属于团队项目事实。
- 为兼容 Agent 生态，项目中没有 `CODEBUDDY.md` 时，WorkBuddy 会读取 `AGENTS.md`；如果两者同时存在，`CODEBUDDY.md` 优先。新项目可使用品牌文件名，跨 Agent 项目则应避免与 `AGENTS.md` 维护两份完整内容。

CLI 和 IDE 的规则扫描、条件触发细节并不完全相同。若团队同时使用两种客户端，核心项目事实放在根目录项目记忆文件，path-scoped 或手动规则只放客户端确实支持的目录中，并在实际版本中验证加载结果。

### 5.2 Auto Memory 和 Typed Memory

WorkBuddy/CodeBuddy 的自动记忆由 Agent 根据会话自主提取，和人维护的 `CODEBUDDY.md` 不同。官方 CLI 文档当前说明：

- 项目自动记忆位于 `~/.codebuddy/memories/{project-id}/`，全局自动记忆位于 `~/.codebuddy/memories/global/`。
- 每个项目有 `MEMORY.md` 索引，启动时自动加载前 200 行；详细内容放入 `preferences.md`、`decisions.md` 等主题文件，按需读取。
- 可以通过 `/memory` 打开管理面板、查看 Auto Memory 目录和 `MEMORY.md`，也可以在设置中切换；文档给出了 `memory.autoMemoryEnabled` 和 `CODEBUDDY_DISABLE_AUTO_MEMORY=1` 配置方式。
- Typed Memory 用 YAML frontmatter 区分 `user`、`feedback`、`project`、`reference` 四类内容，便于按类型管理用户偏好、纠正反馈、项目决策和外部资源。
- WorkBuddy 产品文档说明自动记忆可从会话中抽取事实、偏好和跟进事项，并支持查看、编辑、删除或关闭；因为内容是模型概括，重要决策仍需回到仓库文件核验。

这套设计比单一的项目规则文件更接近“静态规则 + 本地自动记忆 + 结构化类型”的完整记忆系统，但自动记忆仍然是用户侧状态，不是团队通过 Git 共享的项目真相。

### 5.3 适用判断

如果项目只使用 WorkBuddy，可采用 `CODEBUDDY.md` + `.codebuddy/rules/` + `CODEBUDDY.local.md` 的原生布局；如果项目还要兼容 Codex、Pi、OpenCode 和 Claude Code，建议把根目录 `AGENTS.md` 作为共享入口，WorkBuddy 通过兼容读取它，只有确有 WorkBuddy 专属规则时才增加薄的 `CODEBUDDY.md` 或 `.codebuddy/rules/`。

## 横向比较

| Agent | 共享项目入口 | 作用域与加载 | 原生自动记忆 | 自动记忆共享性 | 适合的项目方案 |
|---|---|---|---|---|---|
| Codex / ChatGPT | `AGENTS.md`；ChatGPT Project 另有项目说明、文件和来源 | Codex 全局到项目根再到当前目录，逐级拼接；默认项目指导上限 32 KiB | 有，本地 Codex memories；ChatGPT web memory 是另一套 | Codex 本地，不随仓库；ChatGPT web 按账号/工作区能力管理 | `AGENTS.md` + `docs/`，Project instructions 只做产品层上下文 |
| Claude Code | `CLAUDE.md`、`.claude/rules/` | 全局、托管、项目、local、祖先/子目录；支持 path-scoped rules 和 imports | 有，Auto memory + 子代理独立 memory | 机器本地；同一仓库 worktree 共享，但不跨机器 | `CLAUDE.md` 导入 `AGENTS.md`，复杂规则用 `.claude/rules/` |
| Pi | `AGENTS.md` / `CLAUDE.md`，`.pi/skills/` | 全局与父目录到当前目录，匹配文件拼接；override 替代同级文件 | 核心文档未列原生自动记忆；有会话和压缩 | 会话在本地保存；第三方扩展另行决定 | `AGENTS.md` + `.agents/skills/`，明确区分会话摘要 |
| OpenCode | `AGENTS.md`；可回退 `CLAUDE.md` | 项目向上遍历、全局规则、`opencode.json` instructions 合并 | 核心没有内置自动记忆主流程；可接生态插件 | 取决于插件/后端，默认不应视为 Git 共享 | `AGENTS.md` + `opencode.json` instructions + Skills |
| WorkBuddy / CodeBuddy | `CODEBUDDY.md` 或 `.codebuddy/CODEBUDDY.md`；兼容 `AGENTS.md` | 用户、项目、local、规则和子目录动态加载；IDE 支持 Always/Requested/Manual | 有 Auto Memory 和 Typed Memory | 项目自动记忆在本机；静态项目文件可随 Git 共享 | 多 Agent 用 `AGENTS.md`；纯 WorkBuddy 项目可用原生 `CODEBUDDY.md` |

## 推荐的跨 Agent 落地方案

### 1. 目录布局

```text
repo/
├─ AGENTS.md                       # 跨 Agent 的共享入口，提交到 Git
├─ docs/
│  ├─ architecture.md              # 稳定架构事实，按需读取
│  ├─ decisions/                   # ADR、重要取舍和日期
│  └─ operations.md                # 部署、排障和环境说明
├─ CLAUDE.md                       # 可选：@AGENTS.md + Claude 专属规则
├─ .claude/
│  └─ rules/                       # 可选：Claude 的路径规则
├─ .codebuddy/
│  └─ rules/                       # 可选：WorkBuddy 专属模块化规则
├─ .agents/
│  └─ skills/                      # 可选：跨 Agent Skills
└─ opencode.json                   # 可选：列出额外 instructions
```

不必为了“看起来完整”同时创建所有目录。只有实际使用对应 Agent 或确有路径化规则时才增加适配文件，减少多套规则的漂移。

### 2. `AGENTS.md` 应写什么

建议只保留新会话几乎必需且可验证的内容：

- 项目一句话定位、目录边界和关键入口。
- 安装、构建、测试、lint、类型检查命令，以及命令执行顺序。
- 代码风格、命名、依赖和生成文件约定。
- 不允许做的高风险操作，例如不能读取或提交哪些密钥文件。
- 修改特定目录前必须读取的文档或 Skill。
- 已确认的架构决策和常见陷阱；详细理由链接到 `docs/decisions/`。
- 完成任务前必须运行的最小验证清单。

不建议把完整 API 文档、长篇需求、历史聊天摘要和每次任务的临时状态塞进根文件。根文件越长，越容易触发上下文限制、规则冲突和模型注意力稀释。

### 3. 记忆写入与治理流程

1. Agent 在工作中发现重复纠正、稳定架构事实或新决策时，先判断它属于规则、项目知识还是个人偏好。
2. 影响团队的内容写入 `AGENTS.md`、ADR 或运行手册，并通过正常代码评审进入 Git；只影响个人的内容留在本机 Auto memory 或 local 文件。
3. 对自动记忆设置定期复核：删除过期命令、旧路径、临时分支和未经确认的推断；不要写入密钥、Token、客户数据或不应跨项目传播的内容。
4. 长任务用会话的 resume/compaction 继续工作，但在阶段完成时把目标、决策、验证结果和未决项写入项目文档，避免只留在会话摘要中。
5. 对安全、格式、测试和发布等必须遵守的事项，用 Hook、权限、lint、测试和 CI 做确定性校验；记忆文件只负责帮助 Agent 做出正确的第一步判断。

### 4. 迁移和验证

迁移现有项目时，不要把不同 Agent 的自动记忆目录复制进仓库。建议先选一份共享事实源，通常是 `AGENTS.md`，再按客户端增加薄适配层：Claude 用 `@AGENTS.md`，WorkBuddy 依赖 `AGENTS.md` 回退或只增加专属规则，Pi 和 OpenCode 直接读取 `AGENTS.md`，Codex 使用其原生层级发现。

每次新增或改动规则后，都应在目标客户端新开会话并确认实际加载结果：Codex 可检查 instruction chain 或日志，Claude Code 用 `/context`，Pi 看启动头或 `/reload` 后的资源列表，OpenCode 通过 `/init`/规则配置和实际提示验证，WorkBuddy 询问当前应用规则或使用 `/memory`/规则面板检查。若同一条规则在不同 Agent 上结果不同，应先检查文件优先级、客户端版本和是否被配置禁用，再决定是否增加适配内容。

## 最终建议

**把项目记忆当作一个可审查的文档系统，而不是某个 Agent 的隐藏状态。** 在当前五个 Agent 中，`AGENTS.md` 是最适合作为共享基线的文件名；Claude Code 的 `CLAUDE.md`、WorkBuddy 的 `CODEBUDDY.md` 和各自 Rules 目录是适配层，Codex、Pi、OpenCode 可以直接消费 `AGENTS.md`。自动记忆可以减少重复说明，但必须接受“个人化、可能错误、可能过期、不能替代仓库真相”这四个约束。
