# pen.dev VS Code 插件、Windows 桌面端、MCP 与 CLI 区别调研

> 调研日期：2026-08-20。本文以 pen.dev 官方文档、官方下载页和 VS Code Marketplace 页面为依据。官方文档最后更新时间显示为 2026-08-12，下载页和扩展市场的状态可能继续变化。

## 结论

pen.dev 的四个概念不在同一层级：

- **VS Code 插件**和**Windows 桌面端**都是承载 `.pen` 编辑器的客户端，只是宿主不同。
- **MCP** 是本地运行的协议/工具服务层，让 Claude、Cursor、Codex 等 AI 客户端能够读取和修改 `.pen` 文件；它不是另一个画布客户端。
- **CLI** 是可独立运行的命令行客户端，复用与桌面端和 IDE 插件相同的编辑器引擎，支持无界面、交互式 MCP 工具调用、批处理和导出。

如果主要工作发生在代码仓库和 VS Code 中，优先使用 VS Code 插件；如果需要完整独立画布和内置 AI 对话，使用桌面端；如果需要脚本化、批处理或 CI/CD，使用 CLI；如果要让外部 AI 代理操作设计，则需要 MCP 连接层。

## 四者的层级关系

```text
                   AI 客户端
       Claude / Cursor / Codex / Windsurf / OpenCode
                         |
                         | MCP
                         v
       pen.dev MCP Server（本地，提供设计读写与视觉工具）
              /                    |                    \
             /                     |                     \
   VS Code 插件             Windows 桌面端              CLI
   IDE 内画布                独立画布与 AI Chat          无界面/交互/批处理
```

四种方式共同围绕 `.pen` 文件工作。`.pen` 是基于 JSON 的、可读且适合 Git 版本管理的设计文件格式，可以和源代码放在同一个仓库中。

## 对比表

| 维度 | VS Code 插件 | Windows 桌面端 | MCP | CLI |
|---|---|---|---|---|
| 本质 | VS Code 扩展 | 独立桌面应用 | AI 与 pen.dev 之间的协议/工具服务 | 命令行客户端 |
| 是否有画布 UI | 有，在 VS Code 内打开 `.pen` | 有，独立窗口和完整画布 | 没有，主要提供工具调用 | 默认没有；可连接正在运行的桌面端或插件 |
| 主要入口 | VS Code 扩展市场 `highagency.pencildev` | 官方下载页的 Windows 安装包 | pen.dev 启动时自动运行，本地监听 | `npm install -g @pen.dev/cli` 后使用 `pen` |
| 对代码上下文 | 最直接，可与代码文件同处 IDE | 可通过仓库和 `.pen` 文件协作，但不是 IDE 侧栏 | 由 AI 客户端和工作区权限决定 | 可指定 `--workspace`，适合脚本和流水线 |
| AI 交互 | 使用 IDE 的 AI/Claude Code 面板，并通过 MCP 操作设计 | 内置 AI Chat；也可被外部 AI 通过 MCP 操作 | 提供读写、分析、截图等工具给 AI | `--prompt` 运行 Agent，或交互式直接调用 MCP 工具 |
| 适合场景 | 边写代码边设计、设计与代码双向同步 | 独立设计、完整画布操作、需要内置 AI Chat | 接入多个 AI 客户端、扩展代理能力 | 自动化生成、批量处理、导出、CI/CD |
| 关键限制 | 依赖 VS Code 和插件激活；需要正确打开 `.pen` 文件 | Windows 架构支持需要确认；当前官方下载页只列出 x64 | 本身不能替代画布；基本使用要求 pen.dev 正在运行 | 需要 Node.js 18+；CLI 认证与桌面端/插件不是同一套入口 |

## 1. VS Code 插件

### 定位

VS Code 插件把 pen.dev 画布嵌入开发者的 IDE 工作流。安装插件后，在工作区创建或打开 `.pen` 文件，编辑器右上角会出现 pen.dev 图标；插件侧重点是让设计文件与代码文件处在同一个工作区。

官方下载页链接到 VS Code Marketplace 的 `highagency.pencildev` 扩展。文档给出的基本验证步骤是创建 `test.pen`、打开文件，并在编辑器中确认 pen.dev 图标出现。

### 能力

- 在 IDE 内查看和编辑无限画布、图层、组件、变量等设计内容。
- 让 AI 同时看到 `.pen` 文件和代码库，例如从 `src/components/Button.tsx` 重建设计，或把设计生成 React、Next.js、Vue、Svelte、HTML/CSS 等代码。
- 通过 MCP 让 IDE 中的 AI 客户端读取、修改和截图验证设计。
- 设计文件可以跟代码一起提交 Git，适合按分支和 Pull Request 管理。

### 适合谁

前端工程师、设计工程师，以及希望让设计与实现保持同仓库同步的团队。它是四种方式里“设计和代码切换成本”最低的一种。

### 注意事项

- 插件激活后仍要完成 pen.dev 激活；官方文档还要求为 AI 功能安装并登录 Claude Code。
- 插件未激活时，先确认当前确实打开了 `.pen` 文件，再检查扩展是否启用、MCP 是否连接和 IDE 控制台错误。
- 插件本身不是 CLI；在终端使用 `claude` 是 Claude Code 的命令，而不是 pen.dev 的 `pen` CLI。

## 2. Windows 桌面端

### 定位

桌面端是独立运行的完整画布应用，官方下载页将其描述为具有原生性能的 Desktop app。桌面端内置 AI Chat，适合在不打开 IDE 侧栏的情况下完成设计、选区操作、导入导出和画布探索。

### 当前 Windows 状态

官方下载页当前提供：

- Intel/AMD x64：`Pen-win-x64.exe`
- ARM64：标记为 **Coming soon**

但同一套官方文档的 Troubleshooting 页面仍保留“Windows desktop app：Not currently available”的旧说明，并建议 Windows 用户使用 VS Code 或 Cursor 插件。安装页则写明 pen.dev runs on Windows。这是官方页面之间的明确不一致。

因此，当前可操作结论是：**Windows x64 桌面安装包已经出现在官方 Downloads 页面，可以按该页面尝试；Windows ARM64 尚未提供；不要把旧 Troubleshooting 页面中的不可用描述当作最新下载状态。** 部署到团队前应实际验证安装包、版本和组织策略。

### 与 VS Code 插件的核心区别

- 桌面端有独立窗口和内置 AI Chat；插件使用 IDE 自带的 AI/Claude Code 面板。
- 桌面端适合以画布为主的工作；插件适合以代码仓库为主的工作。
- 桌面端可以作为 MCP 的宿主，CLI 也可以通过 `pen interactive --app desktop` 连接到正在运行的桌面端并实时应用改动。

## 3. MCP

### 定位

MCP（Model Context Protocol）是 AI 客户端访问 pen.dev 的接口层。官方文档将它比作让 AI 以 API 方式读取和修改 `.pen` 文件：pen.dev MCP Server 在本机运行，AI 客户端通过 MCP 连接后调用设计工具。

MCP 不是：

- 不能单独替代桌面端或 IDE 插件的画布界面；
- 不是一个新的 `.pen` 文件格式；
- 不是只读的设计预览接口，官方说明包含完整写入能力。

### 主要能力

官方列出的工具能力包括：

- `execute`：插入、复制、更新、替换、移动、删除节点，读取节点层级，设置变量和主题；
- `get_app_state`：读取文档元数据和结构；
- 通过 `TakeScreenshot` 渲染设计预览，用于视觉验证；
- 通过 `Export` 导出 PNG、JPEG、WEBP、PDF 和 HTML；
- 通过 `get_guidelines` 获取适用于 `.pen` 文件的设计指南和样式；
- 生成或放置图片，并分析布局、边界和可能被裁切的元素。

### 连接方式与隐私

- 基本使用时，MCP 服务会在打开 pen.dev 后自动启动，无需额外配置。
- 官方列出的 AI 客户端包括 Claude Code、Claude Desktop、Cursor、Windsurf、Codex CLI、Antigravity IDE 和 OpenCode CLI。
- 设计操作在本地完成，官方说明设计文件不会因 MCP 本身被发送到远程服务器；使用 AI 功能时，提示词仍会发送给相应的 AI 服务。
- 可以在 Cursor、VS Code 或 Codex 的 MCP 设置/命令中检查 `pencil` 是否出现。

### 适合谁

需要让多个 AI 工具共享设计操作能力，或者希望自己编排“读取设计 → 修改设计 → 截图检查 → 导出”的代理工作流的人。MCP 更像连接和扩展能力，而不是安装后直接使用的产品界面。

## 4. CLI

### 定位

pen.dev CLI 是独立的终端工具，使用与桌面端和 IDE 插件相同的编辑器引擎，并支持 headless 模式。它适合把设计操作纳入脚本、批处理和 CI/CD，而不要求打开 GUI。

安装要求：

```bash
npm install -g @pen.dev/cli
pen version
```

官方文档要求 Node.js 18 或更高版本。

### 三种主要工作模式

#### Agent 模式

用自然语言创建或修改设计：

```bash
pen --out design.pen --prompt "Create a login page with email and password fields"
pen --in existing.pen --out modified.pen --prompt "Add a blue submit button"
```

可以用 `--model` 选择模型，用 `--workspace` 指定工作区，用 `--export` 和 `--export-type` 导出结果。

#### Interactive 模式

在终端直接调用 MCP 工具、读取应用状态、执行设计操作、截图并保存：

```bash
pen interactive -o output.pen
pen interactive -a desktop -i my-design.pen
```

其中 `-a desktop` 或 `-a vscode` 会通过 WebSocket 连接正在运行的应用或扩展；不指定应用时，则启动无界面编辑器。

#### Batch/CI 模式

使用 `--tasks batch.json` 顺序处理多个设计任务。CLI 支持 `PEN_CLI_KEY` 组织级密钥，适合 CI/CD；文档还列出 `ANTHROPIC_API_KEY`、`PEN_API_BASE` 等环境变量。

### 认证和 CLI 的边界

CLI 有自己的认证入口：

- 交互式登录：`pen login`，状态检查：`pen status`；
- CI/CD 使用 `PEN_CLI_KEY`，且该密钥优先于本地会话；
- 本地会话保存为 `~/.pencil/session-cli.json`。

这与扩展/桌面端文档中出现的 `claude` 登录流程不同。`claude` 是 Claude Code CLI；`pen` 是 pen.dev CLI，二者不要混淆。CLI 的默认 Agent 模型是 Claude 系列，但这不意味着它等同于 Claude Code。

## 如何选择

| 需求 | 推荐 | 原因 |
|---|---|---|
| 在写 React/Vue/HTML 时同步调整设计 | VS Code 插件 | 设计文件和源代码在同一 IDE 工作区 |
| 以画布操作为主，需要独立窗口和内置 AI Chat | Windows 桌面端 | 提供独立完整画布；Windows 当前以 x64 安装包为主 |
| 让 Cursor、Codex、Claude 等 AI 操作 `.pen` | MCP | 提供统一的设计读写和视觉工具接口 |
| 生成多个页面、导出图片、跑自动化任务 | CLI | 支持 headless、交互式工具调用和批处理 |
| 将设计任务放进 CI/CD | CLI + `PEN_CLI_KEY` | 支持非交互认证和流水线执行 |
| 需要同时看到设计和代码 | VS Code 插件 + MCP | IDE 负责上下文，MCP 负责 AI 设计操作 |
