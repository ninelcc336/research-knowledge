# sy-style-100 实际用途与能力边界调研

调研日期：**2026-11-16**。

调研对象：[xiaoxiong20xx-code/sy-style-100](https://github.com/xiaoxiong20xx-code/sy-style-100)。本次克隆默认分支并固定核查提交 `e41dee31a5c05dffa12b2f241378e648d2a22df6`，该提交日期为 2026-11-02。

## 1. 结论

**这是一个“代码动画场景库 + 本地视频渲染工具链 + 给 AI 编程助手的制作说明”。最适合制作有明确风格、镜头和节奏的短广告、产品演示、动态图表、片头及视觉短片。**

画面主要由 HTML、Canvas、CSS 和 WebGL 着色器生成；本地 Chromium 按时间逐帧截图，FFmpeg 编码成视频，Python 合成配乐和音效。已有场景可以直接渲染；也可以修改文字、颜色和镜头，或让能写代码的 Agent 继续开发新片。[R][M][D][C][A]

名字中的 **100 是场景数量，不是 100 种风格**：第一期 20 条、第二期沿用同样 20 种风格另做 20 条、行业示例 60 条。源码清点与这一描述一致。README 另推介的 `sy-style-new20` 是独立仓库，其新增风格与“双击安装”等说明不能算成本仓库已经具备的功能。[R]

本次已跑通一条完整 10 秒视频、多个不同风格单帧和文字参数覆盖，也发现两项可复现的 Windows 使用问题。没有批量渲染全部 100 条，不能将作者的“商用水准”描述视为全部作品均已通过质量验收。

## 2. 仓库实际包含什么

| 内容 | 源码数量 | 默认时长 | 用途 |
| --- | ---: | ---: | --- |
| `styles/NN-name/index.html` | 20 | 10 秒 | 第一期风格展示 |
| `vol2/styles/NN-name/index.html` | 20 | 10 秒 | 同风格的新题材、新镜头 |
| `industry/*.html` | 60 | 15 秒 | 每种风格 3 个行业广告示例 |
| `lib/` | 通用时间轴、WebGL、光线步进及各类风格工具 | — | 复用绘图、材质、镜头与后期效果 |
| `comp/` | 展示片、信息卡、转场、封面 | — | 将多个风格组合成展示片 |
| `audio/` | 音效与配乐合成、音频计划 | — | 将音效安排到动作时间点 |
| `AGENTS.md`、`SKILL.md`、`skills/sy-style-100/SKILL.md` | Agent 操作说明 | — | 指导编程助手修改与渲染 |

20 种风格包括：逐帧手绘、等轴 2.5D、扁平矢量、线条动画、3D 渲染、形变动画、贴纸科普、赛博 HUD、拼贴剪贴、弥散渐变与液态玻璃、包豪斯、Synthwave/VHS、像素、液态金属、综艺花字、页面 2.5D 推镜、数据新闻、水墨、黏土定格、蓝图工程图。[S]

行业示例覆盖咖啡店、民宿、婚礼、工厂、教育、律所、美妆、健身、宠物、旅行、家居、游戏、茶庄、文旅、智能硬件等。品牌是虚构示例，行业片的“CRM”“数据分析”“智能锁”等名称表示广告表现对象，不表示仓库实现了这些业务系统。[I]

本次 `git ls-files` 未发现已跟踪的 MP4 或 ZIP；仓库保存的是可渲染源码。README 说行业成片可从 Releases 下载，但本次未检查发布附件的实际完整性和下载可用性。

## 3. 能实现哪些内容

### 3.1 直接生成现有场景的视频

已经写好的场景可以生成 MP4，默认 30 fps，单条含合成配乐与音效。可以一次选多个风格，也可以按行业编号、风格编号、期数或全部批量生成。[M]

```powershell
node make.js list
node make.js style 03
node make.js style 01 13 18
node make.js industry list
node make.js industry 18a
node make.js industry ep4
```

运行这些渲染命令不需要调用语言模型或视频生成模型，也不需要模型 API Key。首次安装运行环境和依赖需要另行准备。

### 3.2 修改文案、品牌及视觉

多数场景通过开头的 `Reel.cfg({...})` 集中保存标题、品牌、标语等字段，底层也支持 URL 查询参数 `cfg` 覆盖。**本次实测将拼贴标题从“今天也要好好创作”换成“代码生成的短片”，未修改场景源码即可出图。**[C]

颜色、布局、镜头、对象、时间点及动作也能修改，但通常要改 JS、CSS 或 GLSL，不是统一的可视化配置表。更换文字后仍需要检查字数、换行和留白；代码能接受字符串不代表版式会自动适应任何长度。

`node make.js brand 中文名 ENGLISH` 提供批量署名替换，但根目录版本只修改第一期 `styles/` 和部分 `comp/` 文件，不遍历 `industry/` 与 `vol2/`。不能把它当成覆盖全部 100 条的品牌配置中心。[M]

### 3.3 制作有设计感的动画与宣传片

已有工具和场景支持：

- 手绘或扁平剧情、人物和动物的风格化动作、像素及黏土表现。
- 拼贴纸张、撕边、印章、材质纹理、阴影与灯光变化。
- 玻璃折射、金属反射、液态形变、粒子、软阴影、景深与辉光。
- 页面分层、光标动作、模拟软件操作和产品功能介绍。
- 数字滚动、折线图、柱状图、热力图和新闻版式的镜头动画。
- 产品爆炸图、装配过程、尺寸线及蓝图向实体外观的过渡。

这些是代码绘制的视觉内容。新增特定商品造型、人物动作或叙事，需要继续写对应场景；没有“任意题材输入后自动套用所有风格”的引擎。[S][G][UI][DATA]

### 3.4 组合展示片、转场和封面

`node make.js reel all` 会组合片头、各风格、信息卡、小球转场、片尾和配乐；可以通过编号选取部分风格。源码的合集音频规划按 **4 秒片头 + 每个风格 10 秒 + 6 秒片尾** 计算，因此 20 个风格为 210 秒。[M][P]

`node make.js cover` 可生成封面。`render.js` 支持指定时间的静帧、指定时间区间、渲染缩放、运动模糊子帧及硬件 GPU 选项。底层帧目录渲染具备断点续跑逻辑；高层命令是否保留中间帧有所不同，行业路径明确复用已完成帧。[D][M]

### 3.5 本地合成配乐和动作音效

Python 使用 NumPy、SciPy 生成音符、节奏、噪声、混响和各类动作音效，基础节拍为 120 BPM，采样率为 48 kHz。场景中的 `cues` 将音效安排到指定秒数；行业片还执行目标为 -15 LUFS、真峰值 -1 dB 的 FFmpeg 响度处理。[A][M]

因此它能够给动画配节奏与音效，但不提供自然语言写歌、真人旁白、声音克隆或对白生成。

### 3.6 让 Agent 在已有工程上继续创作

仓库给出了时间轴约定、确定性绘制方式、风格复用、性能建议和渲染验收步骤。适合把需求交给 Codex、Claude Code、Cursor 等外部编程助手，由助手修改场景再运行工具链。[K]

Skill 的作用是提供工作说明。仓库本身没有内置模型服务、提示词理解后端或自动分镜决策器；一句话出新片需要外部 Agent 的编程与执行能力。

## 4. 不能直接实现哪些内容

下表区分“仓库没有实现”与“通过继续开发可以扩展”，不表示这些需求在技术上永远做不到。

| 需求 | 当前边界 |
| --- | --- |
| 随便输入一段文案，自动生成任意剧情视频 | 没有内置模型或自然语言到场景的流水线；要复用现有场景或让 Agent 编写新代码 |
| 把任意实拍视频转换成水墨、黏土等风格 | 没有通用视频风格迁移、逐帧理解或重绘模型 |
| 真人影视、任意人物表演、口型同步、数字人口播 | 没有这些生成与驱动模块；风格化代码角色与任意真人视频是不同能力 |
| 自动配中文旁白、克隆本人音色、语音识别和自动字幕 | 没有 TTS、ASR、声音克隆、字幕转录管线；画面里的字幕和花字是场景内设计的文字 |
| 导入一堆素材，自动做完整混剪 | 没有素材库检索、镜头语义匹配、实拍高光筛选或通用剪辑时间线 |
| 拖拽剪辑、可视化编排、多轨编辑 | 没有编辑器产品；预览页面只提供播放、暂停与进度拖动 |
| 输出剪映、PR、AE 的可编辑工程 | 没有相关工程格式导出；可编辑源是 HTML/JS/CSS/GLSL，交付通常为帧图、音频和 MP4 |
| 导入任意 CAD、GLB 或 Blender 角色后一键做商品动画 | 没有通用模型导入、骨骼动画和 DCC 工程工作流；主要通过着色器和代码造型 |
| 真实 CRM、经营分析、医学报告分析或工程设计 | 相关行业片是视觉演示；例如门店数据由代码构造，图表不是连接业务数据库得来的分析结论 |
| 自动发布到抖音、小红书、B 站 | 没有账号接入、上传、排期或发布模块 |
| 一键把所有短片改成任意长度和 9:16 竖屏 | 默认坐标与构图是 1920×1080，时间点按 10/15 秒编排；改比例或时长通常要调整场景、镜头、配乐及高层脚本 |
| 实时生成最终高质量视频 | 最终输出采用离线逐帧渲染；3D 与多子帧场景可能较慢 |

其中，“页面 2.5D”示例画面里出现的 **“AI 一键成片”按钮是动画的一部分**。源码注释明确说这是用 DOM 搭出的“看起来可工作的编辑应用”，没有实现对应 AI 剪辑服务。[UI]

## 5. 使用前需要知道的限制

### 5.1 默认“1080p”输出经过较低分辨率渲染后放大

第一期单条和行业片的 `make.js` 明确使用 `--rs 0.633333`，即约 **1216×684** 渲染帧，再用 FFmpeg Lanczos 放大为 **1920×1080**。所以文件分辨率确实是 1080p，但不是这些路径下的原生 1080p 逐帧计算。[M]

底层 `render.js --rs 1` 可以按 1920×1080 渲染，默认设计坐标也支持这一尺寸。原生高分辨率输出可以通过调整调用与工作流实现；不能将默认成片的像素尺寸直接当成原生细节水平。`make.js` 没有将任意 `--rs` 参数透传成统一出片配置。

### 5.2 已确认的 Windows 单帧路径问题

原命令：

```powershell
node make.js still 03 5
```

在本机运行退出码为 0，控制台显示 `still 5 C` 并提示 `✔ out/03_5s.jpg`，但预期图片并未生成，仓库根目录出现一个名为 `C` 的 JPEG 文件。

原因是高层脚本传入 `5:C:\...\out\03_5s.jpg`，底层用 `s.split(':')` 解构时间和文件路径，把盘符后的部分丢掉。[D]

本次验证成功的绕行方法是直接调用底层渲染器，给 `--still` 使用**相对输出路径**，并先确保输出目录存在：

```powershell
New-Item -ItemType Directory -Force out | Out-Null
node render.js styles/03-flat/index.html x --nogpu --still 5:out/check.jpg
```

这项问题不等于整个 Windows 视频渲染不可用；本次 `node make.js style 03` 完整出片成功。

### 5.3 已确认的 Windows 默认编码问题

在本机 Python 默认编码为 CP936/GBK 的环境下：

```powershell
python audio/reelplan.py out/check-plan.json 03
```

读取 UTF-8 的 `comp/meta.js` 时产生 `UnicodeDecodeError: 'gbk' codec can't decode...`。源码的 `open()` 未明确指定编码，合集命令会走到该脚本。[P]

本次通过下面的方式成功生成 20 秒、3 段的单风格合集音频计划：

```powershell
python -X utf8 audio/reelplan.py out/check-plan.json 03
```

若要使用完整 `node make.js reel ...`，可以先在该终端设置 `$env:PYTHONUTF8 = '1'`，或者修改相关文件读写为显式 UTF-8。本次仅验证 UTF-8 模式下的计划生成，没有完成整条合集的端到端渲染。

### 5.4 运行成本、字体和缓存

- 环境：Node.js 18+、Python 3、NumPy/SciPy、Playwright Chromium、FFmpeg，以及中文/英文字体。没有模型推理费用，但会占用本机计算资源和帧图磁盘空间。[R]
- README 给出的软件渲染估计为：平面约 1–10 分钟/10 秒片，WebGL 约 5–40 分钟，较重 3D 约 25–80 分钟。这是作者估计；本次轻量 03 风格的逐帧阶段约 59.6 秒，不能推算全部风格速度。
- `--hwgpu` 让 WebGL 尝试使用硬件显卡，最终 H.264 编码仍使用 `libx264`；它不是自动开启 GPU 视频编码。[M][D]
- 根 README 要求 `Noto Sans CJK SC`、`Noto Serif CJK SC` 和 Inter，特别指出 `Noto Sans SC` 名称不同；第二期文档仍有旧写法。字体缺失可能回退，不能保证字形和排版与作者成片一致。
- 改场景后要注意 `--force`。高层会按已有帧数量跳过完成场景，不会自动根据源码差异判定所有缓存失效。[M]

### 5.5 “纯代码”和“商用水准”的准确理解

场景动画由代码驱动，但仓库也包含 JPEG 和内嵌图片数据，例如拼贴中的照片/截图、页面演示中的预渲染缩略图。因此不宜理解成“完全不使用任何栅格图片，每个像素都现场从零计算”。[IMG]

“商用水准”是作者对效果的描述，不是自动质量保证。不同风格的真实感、产品还原程度、字体和叙事适配需要逐片检查。

仓库代码采用 MIT License，允许使用、修改与商业使用；分发代码时保留相应版权和许可声明。画面中的署名与源代码许可证说明是不同事项。[L]

## 6. 本次实际验证结果

环境：Windows、Node.js 24.9.0、Python 3.12.0、Playwright 1.65.1（由仓库依赖 `^1.48.0` 本次解析得到）、NumPy 2.5.4、SciPy 1.18.1，以及本机已安装的 Chromium 和 FFmpeg。依赖安装与产物均在临时克隆内完成，没有修改上游源码。

| 检查 | 结果 |
| --- | --- |
| 源码数量与引用文件 | 第一期 20、第二期 20、行业 60；行业 JSON 引用的 HTML 全部存在，行业时长均为 15 秒 |
| 风格和行业目录命令 | `list` 与 `industry list` 正常输出 |
| 完整视频 | `node make.js style 03` 成功，逐帧阶段约 59.6 秒 |
| FFprobe | 1920×1080、30 fps、H.264，AAC 双声道 48 kHz，10.000 秒，4,779,198 字节 |
| 视频画面检查 | 抽取六个时间点制作联系表，能看到推进、场景切换及结尾标题 |
| 音频测量 | FFmpeg EBU R128 测得综合响度约 -16.0 LUFS、真峰值约 -2.9 dBFS；这只代表本次 03 风格输出 |
| 其他风格静帧 | 拼贴 09、玻璃 10、行业数据 17c、茶庄水墨 18a 成功，已检查图像 |
| 第二期 | 03 扁平连锁反应在 2 秒和 7 秒成功出图；4.5 秒为源码安排的一帧闪白 |

| 底层视频区间导出 | 03 场景 4.5–5.5 秒成功输出 960×540、30 fps、1 秒 H.264 无声片段 |
| Windows 单帧高层命令 | 复现盘符被截断；相对路径绕行成功 |
| 合集音频计划 | 默认 GBK 失败，`python -X utf8` 成功 |

没有验证的部分：全部 100 条完整输出、行业批量视频、完整合集、所有 3D 的硬件 GPU 路径、原生 4K、Releases 附件、其他操作系统。GitHub API 查询遇到限流，本次未获取 Star、Fork、Issue/PR 或发布状态，不以这些指标判断项目成熟度。

## 7. 适用建议

**如果你的目标是让 Agent 通过代码制作精致的短动画，这个仓库值得作为现成场景与技术底座。** 更换现有示例的文案、颜色与品牌最容易；改变特定物体、剧情和镜头，需要中等到较多的代码工作；制作任意真人、配音口播或通用素材混剪，需要其他工具。

例如，“做一条水墨茶庄广告”“把 SaaS 界面做成 2.5D 功能演示”“生成一段玻璃材质片头”与它的现有能力吻合。“上传我的产品照片就自动生成精确还原的 3D 广告”“把口播音频自动变成带人物和完整字幕的视频”则没有现成流程。
