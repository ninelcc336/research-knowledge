# 目标抖音视频的 Code Agent 制作技术调研

## 1. 调研对象与证据范围

目标链接为[抖音视频 7696843027839227045](https://www.douyin.com/video/7696843027839227045)，页面标题为“claude，我妈问我在干嘛”。浏览器中可见视频时长约 50 秒、9:16 竖屏，标签包含 `#Claude`、`#claudecode` 和 `#incredibox`，页面还有“内容由 AI 生成”的作者声明。

抽查画面可以看到生活化对白、两个角色、代码面板、双语字幕、舞台灯光、镜头推进和节奏化切换。页面没有提供源工程、提示词、素材清单或制作软件，因此下面把“画面中能观察到的事实”和“适合复现它的工程方案”分开描述，不把推断写成作者自述。

## 2. 直接结论

Codex 或 Claude Code 可以承担这类视频的制片和工程工作：把选题写成对白和分镜，把每个镜头转成场景代码，生成字幕和音频时间线，调用浏览器或动画框架渲染，再通过 FFmpeg 合成和导出。Agent 本身不会凭空产出稳定的 MP4；角色资产、声音、浏览器渲染器和编码器仍然是独立环节。

这条视频最适合采用“可复用角色/场景资产 + 代码控制字幕和镜头 + 独立音频 + 自动化渲染”的混合方案。让视频模型一次生成所有镜头，容易遇到角色外观漂移、代码文字错误、中文乱码和镜头衔接不稳定的问题。

## 3. 把画面拆成可实现的技术层

| 画面元素 | 可观察表现 | 工程实现 |
| --- | --- | --- |
| 角色 | 两个角色进行问答，外观和位置需要连续 | 3D 模型、序列帧、2D 角色组件或预渲染视频；角色参数集中配置 |
| 场景 | 紫蓝色背景、灯光、景深和舞台空间 | Three.js、Blender 渲染，或用 SVG/Canvas 做 2D 舞台 |
| 代码面板 | 代码卡片随对白出现并改变位置 | HTML/CSS/SVG/Canvas 组件，代码文本由程序绘制 |
| 字幕 | 英文短句与中文句子按对白切换 | `timeline.json` 中的字幕 cue，使用本地中文字体叠加 |
| 镜头 | 推近、切换、角色与面板同时移动 | Remotion/GSAP 时间线，或 Three.js 相机关键帧 |
| 声音 | 对白、音乐和提示音共同推进节奏 | TTS/真人配音、音效和 BGM 分轨，最后用 FFmpeg 混音 |

核心原则是：画面中的中文、数字和代码不要交给图像或视频生成模型直接绘制，应由代码或剪辑软件叠加；这样才能保证内容准确、可修改和可复用。

## 4. Codex/Claude Code 的职责边界

Agent 适合负责以下工作：

1. 把主题整理成 15–60 秒的对白、镜头表和素材清单。
2. 为每个镜头生成 HTML/SVG/Canvas、Remotion 或 Three.js 组件。
3. 维护统一的字幕、角色、镜头、音频和节拍时间线。
4. 写 Playwright/Chromium、Remotion 和 FFmpeg 的渲染脚本。
5. 从静帧拼图和低清预览中定位字幕越界、角色漂移、掉帧和音画不同步。
6. 根据 QA 结果修改代码或时间码，并只重渲染发生变化的镜头。

Agent 不应被当作以下环节的替代品：角色和场景资产本身、配音音色、音乐版权判断、最终审美取舍，以及平台发布前的人工作品检查。

## 5. 三种可选产线

| 方案 | 主要技术 | 适合情况 | 主要问题 |
| --- | --- | --- | --- |
| 代码合成 | Remotion + React/SVG/Canvas + Playwright + FFmpeg | 字幕、UI、代码面板和抽象动作较多 | 角色质感和复杂 3D 动作需要额外资产 |
| 3D 渲染 | Blender 或 Three.js + 时间线 + FFmpeg | 需要稳定的角色、灯光、景深和镜头运动 | 建模、绑定、材质和渲染成本更高 |
| 剪辑工程 | AI 素材/TTS + 剪映或 CapCut，Agent 生成素材表和粗剪数据 | 已有角色视频或希望快速试做 | 工程自动化和批量复用能力较弱 |

对于第一次复刻，建议从“Remotion + SVG/Canvas + 少量预渲染角色素材”开始。它能先验证字幕、镜头和节奏，后续再把角色替换成 Three.js 或 Blender 场景，时间线数据无需重写。

## 6. 推荐的最小工程

```text
project/
  brief.md                 # 主题、对白、受众和事实来源
  storyboard.json          # 镜头、时长、动作和素材引用
  timeline.json            # 字幕、音频 cue、镜头和节拍
  scenes/                  # Remotion/Canvas/Three.js 场景组件
  assets/
    characters/            # 角色模型、序列帧或透明视频
    backgrounds/           # 背景和灯光素材
    fonts/                 # 中文和英文字体
    audio/                 # 配音、音乐和音效
  render.mjs               # 固定时间取帧、场景渲染和合成
  ffmpeg.ps1               # Windows 下的编码、混音和封装
  qa/                      # 静帧拼图、边界检查和预览输出
```

时间线不应散落在场景代码里。可以用类似下面的数据描述一个镜头：

```json
{
  "id": "shot-03",
  "start": 8.0,
  "end": 14.0,
  "scene": "code-panel",
  "caption": {
    "en": "I am building this",
    "zh": "我正在做这个"
  },
  "action": "panel.slide-in",
  "voice": "voice-03.wav",
  "asset": ["character-a", "panel-default"]
}
```

这样可以单独调整字幕、动作或配音时间，不需要手工修改多处动画代码。

## 7. 从脚本到成片的执行顺序

1. 先写 120–180 字对白，给每句标注角色、情绪和事实来源。
2. 将对白拆成 6–10 个镜头，每个镜头只承担一个动作，例如提问、展示面板、切换角色或回到生活场景。
3. 先生成配音和逐句时间码，再决定字幕和动作的起止时间。
4. 准备两个角色、一个舞台背景、一个代码面板和一套中英文字体；关键文字全部在渲染阶段叠加。
5. 由 Agent 生成场景组件和渲染脚本，先输出 6–12 张静帧，再输出低清预览。
6. 检查字幕安全区、中文字体、角色连续性、动作与台词的对应关系，再渲染 1080×1920 成片。
7. 用 FFmpeg 完成音频混合、编码和封装，并重新打开导出文件检查时长、帧率和声音。

## 8. Windows 环境需要准备的工具

最小配置包括 Node.js、Chromium、Playwright、FFmpeg、本地中文字体和一个可运行的 Remotion 或 Canvas 项目。需要真实 3D 角色时，再增加 Blender 或 Three.js；需要口型同步时，再增加 TTS、ASR 时间码和口型驱动工具。GPU 能缩短 3D 或 WebGL 渲染时间，但不是代码字幕路线的硬性要求。

建议把版本、字体、分辨率、帧率和素材路径固定在项目配置中。否则同一段代码在不同机器上可能出现字体换行、WebGL 行为或音频时长差异。

## 9. 第一条试做的范围

第一条不要直接做完整 50 秒版本。建议先做 15–30 秒、两个角色、六个镜头：开头一个生活化问题，中间两次代码面板变化，结尾一次动作或对白反转。这个范围足以验证角色一致性、双语字幕、镜头节奏和一次完整渲染。

如果静帧检查和低清预览都稳定，再增加复杂的 3D 灯光、口型、粒子和更多代码卡片。这样可以把问题定位到具体镜头，避免整条视频反复生成。

## 10. 主要风险与判断标准

- 角色每次生成的脸、服装和比例不同：优先使用固定模型、序列帧或透明视频，不要逐镜头重新生成角色。
- 中文和代码出现在生成画面里时错误率高：全部改为后期叠加。
- 字幕与配音、动作不同步：以配音时间码为主时间线，字幕和动作都从同一数据生成。
- 3D 渲染在不同电脑表现不同：锁定浏览器、字体、GPU 选项和渲染分辨率，并保留静帧回归样本。
- 音乐盖住对白或平台转码后失真：对白、音乐和音效分轨混音，移动端小音量复听后再导出。

判断是否适合继续代码化，主要看三个指标：镜头是否能通过参数重复生成、修改一句字幕是否只需改数据、单个镜头失败时能否独立重渲染。满足这三点后，Codex 或 Claude Code 才能真正提高系列化制作效率。
