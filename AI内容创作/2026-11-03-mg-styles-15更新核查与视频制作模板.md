### 1.1 配乐库缺项：新片不能直接假定所有乐器可用

README 写到使用 103 个录制乐器采样；本次按固定提交的 Git 文件树与 `lib/audio/samples/index.json` 逐项核对，结果是：**索引有 42 个乐器键、598 个唯一采样路径，主分支实际提交 102 个对应 FLAC，缺 496 个。** 这里采用文件核查结果；102 与 README 的 103 属于口径差异，不当成新增或删减。[S6][S7]

源码中的 `Instrument.pick()` 与 `hit()` 会从索引挑选，`load()` 随后直接读文件，没有先排除缺失路径。例如 `piano/GPiano_sus_A#4_v2_rr1_Player.flac` 确实在索引中而不在主分支文件树中。两条 PR 都给出了新配乐可能因此加载失败的说明。[S4][S5][S8]

PR #2 的办法是保留原选择，遇到不存在的文件时从已有采样中重选，并提供下载构建脚本；PR #3 的办法是补齐文件，PR 描述称增加约 175 MB。两条 PR 宣称的完整音频回归结果属于提交者的验证，本次没有重跑音轨。

**你的模板里应写：先确认选定乐器对应的文件可读取，再编曲；缺失时改用已存在的采样、合成音色或已提供配乐，并说明选择。** 不必为了制作一支新片先补齐全部采样。只有确实需要完整库时，再评估未合并 PR；不能把其中的 `fetch_missing_samples.py` 当作主分支现成命令。

## 2. 这个仓库今天适合怎样使用

它提供的是**代码动效短片的参考工程与制作简报**：提示词描述风格、故事、动作、声音和验收，有执行能力的 Agent 编写 SVG、Canvas、WebGL、Three.js 或 Blender 工程，再渲染为 MP4。它不是上传一句话就返回视频的生成服务，也没有统一的“填表生成器”。[S6][S9]

最值得保留的结构是：**先决定内容 → 选主风格 → 写动作链 → 把风格写成可检查参数 → 静帧和动作预览 → 声音 → 全尺寸导出检查。** 原仓库的片子经过两轮评审修改，公开提示词不包含全部制作对话；作者公布的 AI 评分不能视为独立质量测量。[S6][S10]

想看全部 15 种风格与原文，使用[原调研第 4 节和第 11 节](./2026-10-20-mg-styles-15短片提示词写法与复用模板.md)。本篇重点解决“我自己的视频怎么填”，不重复整份原文存档。

## 3. 先选制作方案，再填模板

下表是本次按内容需求给出的选择建议，不是仓库实测排名。首次尝试可选 A；以解释概念为主选 B；已经有照片或实拍片段选 C。

| 方案 | 更适合的目标 | 主风格与仓库参考 | 建议首片 | 需要准备什么 | 主要工作量 |
| --- | --- | --- | --- | --- | --- |
| A：一件物品串起功能 | 产品介绍、品牌开场、功能记忆点 | `01-flat-vector` 扁平矢量 | 10 秒，横屏，无旁白 | 产品名、一个核心卖点、短文案 | 图形叙事、形变和转场；不用找照片 |
| B：一个概念讲清楚 | 科普、工具知识、流程解释 | `19-paperclip` 贴纸解释 | 30 秒，横屏，有旁白 | 定稿脚本、来源或演示数据、所需图片 | 信息取舍、口播计时、图表与镜头对应 |
| C：事件之后出花字 | 萌宠、vlog、访谈反应、生活段子 | `18-hanazi` 综艺花字 | 10 秒，竖屏 | 真实素材及事件时刻，或明确的照片分镜 | 素材挑选、字幕触发、情绪节奏 |
| D：慢节奏产品主视觉 | 产品预告、界面包装、氛围短片 | `12-aurora-glass` 极光与玻璃 | 10 秒，横屏，无旁白 | 产品名、一个主界面或功能图形 | 折射、高光、字体与缓慢运动的精修 |

这些方案是不同任务的入口。不要在同一支 10 秒片中同时强制包豪斯的无回弹、扁平片的强弹性、像素片的阶梯运动和玻璃片的慢节奏。主风格先选一个，其他效果只服务当前内容。

## 4. 模板的每一章节怎样填写

本篇把原仓库的结构整理成 **12 节中文制作简报**。第 1–8 节决定你的片子，第 9–12 节是可复用的执行与交付要求。不会选技术参数时，可以写“由制作 Agent 依据主风格决定并记录”，不需要自己补齐所有曲线。[S9]

| 章节 | 你应填写的内容 | 填写示例 | 怎样判断写够了 |
| --- | --- | --- | --- |
| 1. 任务与观众 | 给谁看、在哪里用、希望记住的一件事 | 给首次使用者看，记住“点点笔记能记录、整理、回看” | 能用一句话说清目的；不把多个目标全塞进去 |
| 2. 风格与参考 | 一种主风格、3–5 个可见特征；有参考时指明具体参考方面 | 扁平矢量；纯色、单主体、轻回弹、物件带动转场 | 看到静帧和动作后能核查，不能只有“高级、震撼” |
| 3. 输出规格 | 宽高、时长、fps、总帧数、编码、音轨、路径 | 1920×1080，10 秒，30 fps，300 帧，H.264/AAC | 数字一致；横竖屏与真实用途一致 |
| 4. 固定内容与素材 | 不能改的名字、文案、数字；实际文件路径；允许发挥的范围 | “记录、整理、回看”原样保留；图形可重画，产品名不可换 | 固定内容与创作自由的边界明确 |
| 5. 一句话创意 | 用一个具体物件或事件解释主题 | 一张便签变成三张卡片，再被整理成一个勾 | 能想象连续动作，不只是形容词 |
| 6. 分镜与时间表 | 起止时间、主体动作、文案/旁白、转场、声音事件 | 3–5.5 秒：卡片边框扩为分类界面，镜头跟随中间卡片 | 每个镜头有内容；全片时间无缺口、无意外重叠 |
| 7. 标志技法与参数 | 每项特征在哪一段出现，用帧数、比例、像素或曲线说明 | 卡片错峰 3 帧；主体形变约 10%；全片不加渐变 | 能定位到画面与时刻；参数服从当前风格 |
| 8. 声音与旁白 | 有无旁白、逐句内容与节奏；配乐方向；音效触发事件 | 无旁白，120 BPM 轻电子；落地和归档各有重音 | 静音仍懂主体动作，开声后重音与动作一致 |
| 9. 技术路线 | 使用现有框架或交给 Agent 选；是否复用原仓库 | SVG + 自写时间函数；复用 `renderAt(t)` 渲染接口 | 不把 GSAP、Three.js、Blender 全列成必选依赖 |
| 10. 制作流程 | 静帧、动作、声音、全尺寸检查的顺序 | 先看 6–10 张静帧，再做动作预览和最终导出 | 不是只生成工程就宣布完成 |
| 11. 验收与修改 | 内容正确、风格落地、技术规格；按时间码修问题 | 检查缺字、裁切、黑帧、声画重音；修最高影响问题 | 有截图、实际参数和具体问题，不能只有自评分 |
| 12. 交付文件 | 视频、源码、素材来源、时间表、预览及检查说明 | `video.mp4`、工程、`cues.json`、关键帧、`QA.md` | 收到后能播放、能修改、能复现 |

### 4.1 第 2、7 节：把“风格名”变成观众能看到的特征

先挑 3–5 个重要特征，再各写一次“在哪里出现”。例如扁平片写“纯色、约 10% 挤压拉伸、卡片错峰 3 帧、物件铺屏转场”；综艺片写“填充+白描边+彩色外描边，8 帧缩放入场，反应事件后晚 2 帧出现”。这些来自相应原提示词的写法。[S11][S12]

玻璃片可以写“白色填充 5%–10%、约 30 px 背景模糊、1 px 高光边、文字上移 8 px 并淡入”。如要真正的透镜折射，必须单独写明并看画面验证；只加透明圆角卡片不会自动得到折射。[S13]

原提示词的像素参数来自特定画幅。改分辨率时，用设计坐标、比例或明确的缩放规则重新解释；不要要求所有分辨率都用相同的实际像素粗细。

### 4.2 第 4 节：写清“不可改”，否则原模板允许换故事和品牌

原仓库明确授权导演改变概念、文案、节拍和品牌名。已有定稿内容时，改写为：“以下内容原样保留；只能调整镜头、动作和非固定装饰。”如果产品是虚构的就直接注明；使用自己的品牌时列明提供的标识文件，不能让 Agent 临时另造一个同名 Logo。[S9][S11]

素材不要写“从 `/assets/images` 随便挑”，应给实际路径。没有图片时可写“没有外部图片，请用程序图形实现”，或者让 Agent 先查找并记录适用素材。选照片方案时，再提供照片路径及顺序。

### 4.3 第 5、6 节：写“主体动词”，并让上一场带出下一场

可用句式：**在什么时间，哪个主体做什么，变成/揭示什么；哪个元素承担转场；最后停在哪里。** 例如“2.5 秒便签角向外展开，覆盖画面，揭示分类视图”，比“这里顺滑转场”更能约束结果。

建议用“前 0.5 秒看见主题 → 建立 → 升级 → 高潮 → 留出结尾”组织短片。原仓库常把高潮放在约全长 60%–75% 处，结尾完整构图保持约 0.8–1.2 秒；这些是创作参考，长解说片不必机械套用每个比例。[S10]

### 4.4 第 8 节：有旁白时，先计时再排镜头

旁白内容、屏幕强调字和音效事件分别填写。旁白讲一句话，屏幕可以只强调关键词；字幕是否逐句显示另写清楚。先得到实际口播时长及句子边界，再让画面跟随，不把超长文案硬压进既定 10 秒。

配乐写流派、速度和段落变化即可，不要求你会作曲。原仓库的 `-14 LUFS integrated`、`true peak ≤ -1 dBTP` 可作为本项目混音目标，**并非本次查到的各平台统一发布要求**。最终应测编码后的文件，不能只看音频脚本中的设定值。

### 4.5 第 9–12 节：一般可沿用，但不能与第 3 节冲突

原仓库渲染器读取 `window.DEMO = {width, height, fps, duration}`，调用 `window.renderAt(t)`，并等待 `window.__ready === true` 与字体就绪。其接口可复用；改用别的帧驱动框架时，用该框架的等价实现，不必再包一套无用接口。[S14]

“按任意时间可重复取帧”需要保留。随机固定种子；物理可以预计算；不要依赖从第 0 秒连续播放到当前帧才能正确显示的隐藏状态。制作流程和评审里残留的“精确 10 秒”也要随本片时长一起改。

# 9. 技术路线
优先遵循当前项目；新项目按本片主风格选择最少且合适的技术。
纯 2D 优先 SVG/Canvas；确实需要三维或 shader 时再选择 Three.js/WebGL/Blender。
如复用 mg-styles-15：提供 window.DEMO、window.renderAt(t)，
资源准备完成后置 window.__ready = true，并按其渲染器导出。
如用其他帧驱动框架，采用等价实现即可。
每帧由时间/帧编号确定；随机固定种子；物理预计算或能按时间直接求值。

## 7. 时长和画幅变化时，哪些地方必须一起改

**30 秒知识片不能只把 Output 的 10 改成 30。** 同时更新任务开头、分镜时间、总帧数、音轨、共同时间表、工程配置和评审规格。下面是设计起点，不是平台标准或仓库新增能力。

| 成片 | 总帧数（30 fps） | 建议组织 | 特别要处理的地方 |
| --- | --- | --- | --- |
| 10 秒 | 300 | 一个主题、3–5 个主要动作、一个结尾 | 文案短，别塞完整长解说 |
| 30 秒 | 900 | 问题 → 例子/证据 → 对比/解释 → 结论 | 先计时旁白；让图表真正停下来给人读 |
| 60 秒 | 1800 | 开头问题 + 2–3 个有因果关系的小段 + 回答问题 | 每段重新组织动作和信息，不把 10 秒模板重复六遍 |

## 9. 在 Windows 上复用工程的实际入口

制作新片时可以借用原仓库渲染器和音频工具，不必复制所有演示工程。README 给出的环境是 Node.js 22.12+、Python 3.11+、Chrome、FFmpeg；3D 片另需 Blender。字体文件未随仓库提供，需要按清单补齐或替换，并检查替换后的排版。[S6][S16]

**这些是源码文档中的运行入口，本次没有安装依赖、运行渲染器或验证 Windows 兼容性。** 原渲染器默认 Chrome 路径是 macOS，非 macOS 的 GPU 参数也没有单独区分 Windows；Windows 应设置真实 `MG_CHROME`，检查启动日志，必要时按本机调整 `MG_GPU_ARGS`。锁目录还写为 `/tmp/mg-render-slots`，复用时应确认其在本机可写或调整为本机临时目录。[S14]

复现 01 的顺序是：在仓库根目录安装 npm 和 Python 依赖，补齐该片字体，执行 `python demos/01-flat-vector/audio.py`，再执行 `node harness/render.mjs demos/01-flat-vector`。先用同一渲染器的 `--stills 0,1,3,6,8,9.5` 检查静帧，再做完整导出。渲染器本身启动本地服务；不要把这些命令当成已经在本机通过的结果。[S14]

如果选 Blender 片，网页合成之前还要完成其序列帧生成。不要把提示词里的 Metal GPU 写成 Windows 的必需条件；04 的说明还给出了 NVIDIA 的 `MG_DEVICE=OPTIX` 入口，实际设备是否可用需在制作时确认。[S17]
