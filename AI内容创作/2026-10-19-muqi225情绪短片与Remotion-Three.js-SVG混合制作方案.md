# muqi225 情绪短片与 Remotion、Three.js、SVG 混合制作方案

调研日期：2026-10-19。

## 1. 结论与证据边界

抖音账号 `muqi225` 的昵称为“爱吃西兰花🥦”，目标合集为“AI镜头里的情绪碎片”。从本次检查的画面看，短片更符合固定三维资产经过动画和镜头调度后渲染的特征；Three.js/WebGL 和 Blender 都是合理候选。仅凭成片不能确定具体软件，也不能完全排除视频生成模型或混合制作。

本次没有找到作者明确披露制作软件的说明、工程文件或制作教程。视频标题中的 Claude 是剧情角色，`#Claude` 标签和“内容由 AI 生成”声明均不能证明作者使用了 Claude 写代码，也不能证明使用了 Seedance 等视频生成模型。用户提到的 `Seedance 2.5` 仅作为候选路线，本次未核查该具体版本的产品状态和能力。

对于自行制作同类系列短片，推荐 **Remotion + React Three Fiber + Three.js + @remotion/three**，采用“SVG 远景 + 三维角色和接触物体 + 二维字幕”的混合方案。这是复现与生产方案建议，不是对原作者工作流的确认。

本次完成了账号、合集、代表画面和 Remotion 官方文档核查；尚未搭建或渲染样片，因此没有实测画质、渲染速度、硬件成本或跨机器一致性。

## 3. 制作路线比较

| 路线 | 对本类短片的作用 | 判断边界 |
| --- | --- | --- |
| HTML/CSS/SVG | 绘制字幕、界面、远景、装饰和前景遮罩 | 普通二维布局不适合作为立体角色与真实空间关系的主要实现 |
| Three.js/WebGL | 创建或加载固定模型，控制材质、灯光、阴影和摄像机 | 符合画面特征，适合代码化复现；没有原作者使用该技术的直接证据 |
| Blender | 建模、绑定、动画、灯光和离线渲染，也可导出模型供 Web 使用 | 同样符合画面特征；成片无法确认是否使用 |
| Seedance 等视频生成模型 | 生成镜头、素材或风格变体 | 本次未发现确认其为主要制作工具的证据，不能据此断言未使用 |

前端三维与 Blender 可以组合：在 Blender 制作角色并导出 GLB，再由 Three.js 控制动作与镜头，交给 Remotion 组织时间线和导出。

## 4. Remotion 与 Three.js 的职责

Remotion 官方提供 `@remotion/three`，通过 `ThreeCanvas` 集成 React Three Fiber 与 Remotion。该组合适合角色和场景固定、每集主要更换对白、动作和镜头的系列内容。

| 组成 | 主要职责 |
| --- | --- |
| Remotion | 镜头时序、配音、字幕、转场、预览与最终视频导出 |
| Three.js | 三维角色、场景、材质、灯光、阴影和摄像机 |
| React Three Fiber | 用 React 组件组织和控制 Three.js 场景 |
| @remotion/three | 通过 ThreeCanvas 将三维渲染与视频帧同步 |

动画应以 Remotion 的 `useCurrentFrame()` 为统一时间来源，结合 `interpolate()`、`spring()` 或显式时间函数，计算当前帧的角色姿态、相机位置和效果参数。官方文档明确要求不要依赖普通 R3F `useFrame()` 动画循环推进视频动画，以保证暂停、回拖和逐帧导出时的状态一致。

采用该方案后，优先用 Remotion 的帧驱动动画替代独立运行的 GSAP 时间轴。确需使用 GSAP 时，时间轴也应由帧号定位，不能各自按真实时间播放。眨眼、粒子和随机动作需要使用可重复的参数或固定种子。

`ThreeCanvas` 需要显式设置画布宽高；其内部使用 `Sequence` 时应设置 `layout="none"`，避免插入不适用于三维渲染器的 DOM 包装。正式渲染还应按官方文档配置 WebGL 渲染后端；材质、模型和字体加载须在截图前完成。

## 5. SVG 背景与三维角色的混合方式

“角色在 SVG 环境里活动”可以通过二维合成，也可以把 SVG 作为三维场景的贴图。两种方式的主要区别是是否共享摄像机和深度。

### 5.1 二维背景叠加透明三维画面

在 Remotion 中按下列顺序叠放：

```text
背景层：SVG 天空、楼群、远处灯光
角色层：透明 ThreeCanvas，包含地面、角色和交互道具
前景层：SVG 窗框、植物或装饰遮罩
字幕层：React / SVG 字幕与提示
```

SVG 可由代码批量生成建筑、窗户和装饰，动画仍由视频帧号驱动。这种方式适合固定机位、人物对话、平面缩放和有限镜头移动。

SVG 与 ThreeCanvas 不共享三维深度。角色走到 SVG 树木或窗框后面时，需要拆分前后景、使用遮罩或显式调整层级。三维摄像机移动也不会自动改变独立 SVG 背景的透视，不能把两层当成天然一致的三维空间。

### 5.2 将 SVG 放到三维场景的平面上

把天空、远楼和近楼分别制成纹理，放在不同距离的平面上，再把人物放在前方。相机移动时，各层能够产生视差，并参与同一场景的遮挡关系。这是一种 2.5D 布景。

SVG 作为纹理后仍是平面图像，不会自动生成建筑侧面和体积。大幅环绕镜头会暴露纸片特征，需要改用立体模型或针对镜头补充布景。纹理清晰度还取决于转换和采样分辨率，不能把源 SVG 的矢量特性等同于 GPU 纹理无限清晰。

### 5.3 推荐的场景分工

| 内容 | 推荐实现 | 原因 |
| --- | --- | --- |
| 天空、远楼、窗外灯光 | SVG 背景或分层贴图平面 | 减少建模工作，便于参数化复用 |
| 人物与小 Claude | 固定三维模型或几何体组合 | 保持外观，便于复用动作和多角度镜头 |
| 地面、桌面、椅子、接触道具 | 简单三维几何体或模型 | 建立接触位置、阴影和遮挡，减少悬浮感 |
| 随镜头转动的屏幕和代码面板 | 三维平面加程序绘制纹理 | 使文字准确并跟随透视 |
| 字幕、固定提示和标注 | React / SVG | 保持清晰、可编辑和时间码可控 |

独立二维 SVG 不会自动接收三维灯光和阴影。需要角色落地阴影的表面，应使用三维接收平面或明确设计的合成阴影。

## 6. 最小试做范围与验证

第一版建议做15秒、9:16竖屏、两个角色、一个场景和三个镜头，先完成一个完整的制作与导出闭环：

1. 写对白并完成配音，确定每句话和停顿的时间。
2. 建立人物、小 Claude、地面和桌面，绘制一套 SVG 远景。
3. 用同一帧号驱动抬手、点头、转身、简单口型与镜头变化。
4. 配置蓝紫色灯光、屏幕发光和适量景深，叠加双语字幕。
5. 先检查静帧，再导出低清预览，最后验证正式成片。

验证重点是：角色结构是否连续、脚底和座位接触是否成立、前后遮挡是否正确、镜头运动与背景是否协调、字幕和声音是否同步，以及暂停、回拖后同一帧是否一致。画质主要取决于造型、灯光、构图和动作节奏，选择 Remotion 本身并不保证这些质量。
