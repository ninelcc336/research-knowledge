# Breeze TTS 2 项目调研

调研日期：2026-11-08。研究对象为 BreezeBlue 的 Breeze TTS 2，包括官方开放权重、PyTorch 推理代码、托管平台与 API，并补充 ComfyUI、MLX 社区入口。本文中的 breezeTTS2、Breeze-TTS-2 均指该项目。

## 1. 结论与选型建议

**值得试用，主要价值是同一模型同时支持音色设计、声音克隆、参考音色下的自然语言表演控制，以及音频流式输出。适合中英角色对白、情绪配音和实时语音原型；本地商业配音不能直接使用其免费开放权重。**

最影响选择的六点：

- **代码与模型许可不同。** 推理代码为 Apache-2.0；模型权重、量化和微调等衍生模型，以及本地生成的音频，适用研究与非商业许可。广告、商单、变现视频、客户项目和超出有限评估的企业内部生产用途，均不能因为代码是 Apache-2.0 就直接开展。[S1][S3]
- **公开权重支持中英双语，云端多语言版支持 51 种语言。** 当前云端正式模型 ID 为 `breeze-tts-2-multilingual`，公开模型卡仍只承诺 English/Chinese；不能把官网的多语言宣传直接套到本地模型。[S2][S4][S5]
- **“低于 40ms”有严格条件。** 官方指 NVIDIA H100、快速路径、完成预热后的 TTFA；另一个云 API 基准给出 p50 127.2ms、p95 159.3ms。它们不是同一个测试，也不能作为 Windows 家用显卡的性能承诺。[S1][S4][S9]
- **“开放权重第一”不能作为当前结论。** 本次读取的 Artificial Analysis 榜单中，Breeze TTS 2 列第 14、Elo 1228±13；Fish Audio Drama 3 等带权重链接的模型已排在前面。官方 README 的相关宣传与本次榜单快照不一致。[S1][S6]
- **官方本地服务仍较轻量。** 单个服务进程只处理一个推理请求，流式和批量请求共用同一槽位，忙时返回 HTTP 409；它不是开箱即用的多用户高吞吐服务。[S10]
- **长文稳定性需要单独验证。** Issue #25 有跨段音色、音量和语速不一致的反馈；维护者给出了参考音频预处理建议，但没有宣布问题彻底解决。固定 seed 不等于不同文本之间音色绝对一致。[S16]

本次完成了官方资料、许可、当前源码和公开问题核查；没有下载模型权重、在本机运行推理、试听生成音频或做主观盲测。以下音质与性能判断均按证据来源限定范围。

从配置和加载代码看，主要链路是 **T5Gemma2 文本编码器 → Qwen3 风格自回归 backbone → depth decoder → 随权重附带的 Qwen3-TTS 音频 tokenizer/decoder**。音频按 12.5 帧/秒组织，每帧使用 16 个 codebook。它是独立的 TTS 模型，不能理解为换皮调用 Qwen3-TTS API；仓库也没有提供完整的官方训练或微调教程。[S2][S12]

## 3. 能做什么，如何控制

### 3.1 三种主要生成方式

| 模式 | 输入 | 作用 | 官方建议 |
| --- | --- | --- | --- |
| Voice Design | 目标文本 + 声音描述 | 无需参考录音，描述年龄感、音高、质感、角色与说话方式来创建声音 | 指令与正文用同一种语言，`cfg_scale=4` |
| Voice Clone | 目标文本 + 参考音频 + 准确转写 | 尽量继承参考的音色、节奏、情绪与风格 | 不传 `instruction`；默认 CFG 为 1 |
| Voice Direction | 上述克隆输入 + 表演指令 | 保留参考说话者身份，同时调整语气、情绪、语速与表达方式 | `cfg_scale=4` 增强指令遵循 |

本地模板路由已在源码中核对：有参考但无指令走克隆；有参考且有指令走 Direction；无参考且有指令走 Design。参考音频和 `ref_text` 必须成对传入。**给克隆请求加上 `instruction` 会改变生成模式。**[S1][S10][S12]

参考录音应为单人、干净、无明显背景噪声的真实讲话，避免循环拼接。转写必须与所用录音的完整内容对应，音频中重复的词也应写入转写。公开本地接口不自动替用户完成 ASR 转写。[S1][S12]

### 3.2 情绪、语速与非语言事件

中文正文支持 `[笑]`、`[叹气]`、`[咳嗽]`、`[清嗓子]`；英文示例使用 `(laugh)`、`(sigh)`、`(cough)`、`(clears throat)`。这些标签直接放入朗读文本，适合角色对白的停顿和动作表达。[S1]

建议把稳定的角色特征与临时表演要求写清楚，例如：

```text
目标文本：[叹气] 我不是不相信你，只是这次真的不能再出错了。
指令：一位三十岁左右的男性，声音低沉略沙哑；压低声音，语速稍慢，表现出疲惫和克制的担忧，避免夸张哭腔。
```

无参考音频时，这是音色设计；配上参考音频和准确转写时，就是对该参考音色的表演控制。这里的提示词是建议写法，未进行本机生成验证。

自然语言“慢一些”属于模型表演控制，并不保证精确秒数。当前官方本地 CLI/API 没有等价于精确目标时长的参数。云端 HTTP 的 `speed` 是调整最终音频整体节奏的另一层能力，实时 WebSocket 不支持该参数；不能混同为本地模型的原生精确时长控制。[S10][S12][S20]

### 3.3 长文与多角色边界

本地 CLI 和 API 的当前生成上限为 1500 个音频 token，按 12.5 帧/秒计算，理论对应约 120 秒；参考、提示和上下文占用可能使可用容量更短。**120 秒不是保证每次都能完整输出的时长。**[S10][S12][S16]

长文应优先保留容量内完整、适度长的段落，在段落或完整句子处拆分，避免把每个短句都独立生成。跨段复用同一份处理后的参考音频及转写，并保持采样配置一致；衔接处可适当留白并统一响度，但这些处理无法纠正真正的音色变化。[S16]

官方公开 CLI/API 主要面向单个说话者的一次生成。ComfyUI 社区插件另提供最多 8 个 Speaker 节点的对白编排，按角色逐轮生成并拼接；这是上层工作流能力，不应描述为官方基础模型已经提供完整的多角色播客制作系统。[S10][S12][S18]

## 4. 音质和速度证据怎样理解

### 4.1 能力评测与第三方偏好榜

| 证据 | 发布值或本次快照 | 能支持的判断 |
| --- | --- | --- |
| 官方 Voice Design Benchmark | Role Fit 78.02；Voice Diversity 708；Transcript Pass 98.5% | 在该套角色描述与评测规则下，声音设计有竞争力 |
| 官方 Voice Direction Benchmark | VDS 4.25；SIM 0.67 | 在该套表演指令下，能兼顾指令遵循与参考说话者相似度 |
| Artificial Analysis 当前读取快照 | 列表第 14；Elo 1228±13；2,778 次比较 | 在该平台偏好评测中表现较强，但并非当前总榜或开放权重第一 |

前两套 benchmark 由 BreezeBlue 自己发布。Design 默认使用 `google/gemini-3.1-pro-preview` 作为评审，Role Fit 是分数均值乘 20，且排除 transcript gate 为 fail 的样本；Diversity 是在指定嵌入模型和聚类阈值下的簇数，**708 不代表购买后可以稳定调用的 708 个预设角色**。Direction 使用同一类模型评审，并结合说话者嵌入相似度。它们可复现方法，但不能替代独立人类盲测或本项目中文脚本测试。[S4][S7][S8]

Artificial Analysis 为动态榜单，当前分数不能永久固定；其置信区间也不支持把相近模型排位理解为绝对音质差距。本次应保留官方“#1”宣传已经需要更新这一事实，而不是沿用旧图得出排名结论。该榜单展示的 Breeze 价格为 $34/百万字符，与当前官网定价不同，本文计费以官网为准。[S6][S13]

### 4.2 三种延迟口径

| 场景 | 数字 | 条件与限制 |
| --- | --- | --- |
| 官方本地快速路径 | TTFA <40ms；RTF 0.32，约 3.1 倍实时 | NVIDIA H100，完成预热，启用快速路径；不是冷启动或消费级 GPU 数据 |
| 官方托管服务基准 | TTFA p50 127.2ms；p95 159.3ms | API 端到端基准；不能与纯本地推理时延直接相减或比较 |
| ComfyUI 社区测量示例 | RTX 5090、SDPA 下 bf16 RTF 5.68，INT8 hybrid 5.64 | 该插件所列路径的数据，明显慢于实时；插件另有 CUDA Graph 模式，不代表所有配置同速 |

RTF = 生成耗时 / 生成音频时长，低于 1 才快于实时。社区插件的 eager、动态显存和量化路径不能与官方 H100 快速路径混用指标。[S1][S18]

官方 Latency Benchmark 标准套件使用 40 条英文文本，每模型先做 3 次不计入统计的预热；同模型请求串行，使用预热后的长连接。TTFA 还考虑音频开头的静音，区别于收到第一个非空音频块的 TTFB。该测试不能直接证明中文、冷连接、多并发或本地消费级显卡的结果。[S9]

完整语音助手还需要 ASR、对话模型、文本分块、播放缓冲和打断处理；Breeze TTS 2 只覆盖文字到语音这一环节。要判断交互速度，应记录用户停止讲话到实际听见响应的总时间。

## 5. 本地部署与 Windows 路线

### 5.1 资源要求

| 配置 | 官方单请求显存说明 | 建议 |
| --- | --- | --- |
| 默认 eager 推理 | 约 7.7 GiB | 官方建议至少 12 GB NVIDIA GPU |
| `--fast-all` | 约 14.4 GiB | 官方建议 24 GB GPU，并接受额外冷启动与预热时间 |
| 批量合成 | 随批量大小、序列长度增加 | 从小 batch 开始；不能用 7.7 GiB 推断 128 条也能运行 |
| CPU | 底层生成存在社区可运行反馈 | 官方主 CLI/API 的流式 runtime 要求 CUDA，不作为实时使用首选 |

官方模型的两片主权重和独立音频 tokenizer 合计约 7.65 GB，另有约 35 MB 的 tokenizer/config 等文件；这是下载文件量，不是显存预算。环境、Docker 镜像和缓存还需要额外磁盘空间。[S1][S2]

当前固定依赖包括 PyTorch/torchaudio 2.9.1、Transformers 4.57.3、qwen-tts 0.1.1。官方 Docker 基于 CUDA 12.8 的 PyTorch 镜像，构建 FlashAttention 2.8.3，默认架构为 H100/Hopper 的 sm90，A100 示例设为 sm80；不能直接把默认构建命令当作任意显卡配置。[S11]

### 5.2 在本项目 Windows 环境中的选择

**优先路线：NVIDIA GPU + WSL2 Linux，或直接使用 Linux GPU 主机。** 这是结合官方 Linux 支持条件给出的部署建议，不是本次已经完成的 WSL2 兼容性验证。

希望沿用图形工作流时，可评估 `Saganaki22/ComfyUI-Breeze-TTS-2`，它提供克隆、设计、Direction、Whisper 转写和多角色节点，并有 INT8 hybrid 等检查点。其 README 给出的显存约为 5.3–7.5 GiB，但随版本、dtype 和解码方式变化；本次没有验证 Windows 安装和音质损失，不能据此保证任意 8 GB 显卡可用。[S18]

Apple Silicon 可参考 `mlx-community` 的 BF16、8bit、4bit 转换模型；模型卡明确说明是非官方、无隶属关系的移植。社区移植、量化和 ComfyUI 包装都不改变原模型的非商业限制。[S3][S18][S19]

### 5.3 可复现的最小本地尝试

以下为 Linux/WSL2 Bash 命令，已与源码参数核对，未在本机执行；先用默认 eager 路径确认生成，再决定是否尝试 `--fast-all`。

```bash
git clone https://github.com/breezeblue-ai/breeze-tts.git
cd breeze-tts
git checkout daa6cb2efe5471f09369229f322d20bb956cb3c3
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

hf download BreezeBlue/Breeze-TTS-2 \
  --revision 3e28c5151381a722f1d8661b4118c298caa77aa4 \
  --local-dir ../breeze-tts-2

python infer.py ../breeze-tts-2 \
  --text "[笑] 欢迎来到今天的故事时间，我们现在开始。" \
  --instruction "一位温柔自信的年轻女性，声音清晰，语气亲切，表达轻快自然。" \
  --cfg-scale 4 \
  --seed 42 \
  --output outputs/design.wav
```

克隆时补上 `--ref-audio reference.wav --ref-text "与录音完全一致的文字"`，去掉 `--instruction` 并使用 `--cfg-scale 1`。需要同一音色改变表演时，保留参考输入，再添加指令并尝试 CFG 4。[S1][S12]

## 6. 接入 Agent、前端与内容制作流程

### 6.1 本地 HTTP API

```bash
python -m breeze_infer.api ../breeze-tts-2 \
  --host 127.0.0.1 --port 7860

curl -X POST http://127.0.0.1:7860/v1/audio/speech \
  -F "text=[叹气] 这件事，我们需要再认真谈一次。" \
  -F "instruction=声音低沉，语速稍慢，语气克制而严肃。" \
  -F "cfg_scale=4" \
  -F "seed=42" \
  --output speech.pcm

ffmpeg -f s16le -ar 24000 -ac 1 -i speech.pcm speech.wav
```

响应是 24kHz 单声道 s16le 裸 PCM，不带 WAV 头；只改扩展名不会变成 WAV。前端可以按采样格式边收边播放，离线保存则按上例封装。虽然路径是 `/v1/audio/speech`，请求却是 multipart 表单，不是 OpenAI 风格的 JSON 请求，不能只替换通用 SDK 的 base URL 就认为兼容。[S10]

服务另有 `/health`、`/v1/model` 和 `/v1/audio/speech/batch`。Batch 接收最多 128 个非空文本，共用同一套参考与指令，返回按顺序拼接的 PCM，通过 `X-Segment-Bytes` 识别分段长度；它是批量接口，不是 128 个流式会话并发。官方服务繁忙时返回 409，接入方如有多请求需求，需要安排队列或评估其他服务实现。[S1][S10]

本地 API 接收完整 `text` 后分块输出音频；截至本次源码未发现对外 WebSocket 逐步追加文本的接口。因此，“本地支持流式音频输出”与“LLM 边产文本、TTS 边接收追加文本”应分开描述。[S10]

### 6.2 托管 API

云端提供 HTTP 一次性、异步和流式合成，以及实时 WebSocket：

- HTTP 流式：`POST /v1/text-to-speech/{voice_id}/stream`。
- 实时文本追加：`wss://api.breeze.blue/v1/text-to-speech/{voice_id}/stream-input`，可在多轮之间复用连接。
- 官方有 Python、TypeScript SDK 和 CLI；接入使用保存后的 `voice_id`，与本地每次传参考录音的接口不同。

当前 HTTP 请求默认最多 1000 字符，经批准可提高但上限为 2000；超长拒绝而非自动截断。中文非流式请求显式指定 `language_code=zh` 时，超过 500 字符会按规则分段合成后拼接；该处理不等于本地权重自动获得同样的长文工作流。实时输出可选 PCM 或 MP3，均为 24kHz 单声道。[S20]

云端创建克隆音色时会转写录音，从上传内容前 60 秒中选择最多 30 秒、尽量完整的片段，归一化至 -18 LUFS，并保存片段与匹配转写。当前指南中的可选降噪默认关闭；不能假设每份录音都已经降噪。同一原始录音直接交给本地模型，与云平台处理后的参考输入并不相同。[S21]

### 6.3 用于短视频、Remotion 或角色对白

建议采用“脚本与角色表 → 分角色合成音频 → 校对漏读与发音 → 转写/词级对齐 → 时间线与字幕 → 视频渲染”的流程。Breeze 负责音频生成；字幕时间戳、精确镜头同步和口型动画需要其他组件。

对叙事短片，先设计并挑选角色声音，再固定参考素材、匹配转写和参数，逐段控制情绪。对有商业收益的发布，应先确定采用付费云端产出或已获授权的本地方案，再生成正式素材，避免拿非商业试音直接当作商用成片音轨。[S3][S15]

## 7. 许可、云端计费与成本

### 7.1 哪些用法获得了授权

| 用法 | 当前公开条款 |
| --- | --- |
| 研究、教学、个人非商业实验 | 模型许可允许；企业有限内部评估本身不因企业身份而自动成为商业使用 |
| 本地生成商单、广告、变现视频或客户配音 | 需要另行取得 BreezeBlue 书面商业许可 |
| 本地模型用于企业生产内部流程 | 超出有限评估，属于许可列举的商业用途 |
| 量化、LoRA、微调或衍生模型 | 在许可允许的研究/非商业范围内进行；衍生模型仍受原许可约束 |
| 使用产出改进其他生成模型 | 有额外训练、蒸馏等限制，不能视作可自由使用的合成训练集 |
| 免费云端账号，或仅单独购买 credits | 云端产出仅限个人非商业使用；只充值不获得商用权 |

模型许可证为 **BreezeBlue Research and Non-Commercial License v1.1，更新于 2026-09-01**，正文明确表示它不是开源许可证。因此，准确称呼是“开放权重、代码 Apache-2.0”，不宜概括成“Apache 开源、免费商用”。[S3][S15]

云端条款还表示，除非通过所提供的控制退出，提交的数据可用于训练和改进；需要预先同意的地区按相应要求处理。若试用涉及不希望参与训练的参考录音，应检查账号中的相应选项。这里只记录与部署路线直接有关的数据使用差异。[S15]

## 8. 已知问题与建议试用项目

| 事项 | 本次证据 | 对实际试用的影响 |
| --- | --- | --- |
| 跨段音色/音量/语速变化 | Issue #25 仍开放；维护者承认对 seed 敏感，未建立完全解决的结论 | 先测试连续多段，不能凭一条展示音频判断长文可用 |
| 个别中文词漏音或发音异常 | Issue #30 报告托管 API 将“环境变量”中的“量”读弱或漏掉 | 这是单个公开报告，不能推广为全局缺陷；应加入自己的专业词测试 |
| CPU 与实时入口不同 | 主流式 runtime 明确要求 CUDA；Issue #29 提出 CPU 原生 generate 示例 | 底层能加载 CPU 不等于官方 CLI 可直接提供 CPU 实时服务 |
| 同名产品能力范围不同 | 本地双语权重、云端多语言模型和平台预处理分别存在 | 验证时固定模型、代码提交、参数和入口 |
| 排名和价格宣传存在时间差 | README 排名与当前 AA 快照不同；AA 价格与官网不同 | 把宣传、当前榜单、当前价格分别记录 |

推荐最小试用集如下，属于后续验证方案，**本次未执行**：

1. 用同一段 150–250 字中文，分别做 Design、Clone、Direction；检查漏读、多音字、英文缩写与事件标签。
2. 同一参考录音、转写和参数连续生成 6 个段落，再生成一段容量内的合并文本；听辨并记录音色、音量和语速变化。
3. 给同一句台词分别设置“平静、疲惫、压低声音紧张、愤怒但克制”；检查能否改变表演而保持说话者身份。
4. 在实际 GPU 上分别记录 eager 和 fast 的冷启动、预热、TTFA、RTF、峰值显存；云端另记网络与实际可听见响应时间。
5. 若要接在线产品，验证第二请求返回 409 时的行为，以及 batch 是否会阻塞当前交互链路。

**个人研究或非商业角色配音：可把它列入试用名单；商业内容：先评估付费云端或书面授权；本地实时产品：重点验证硬件、单请求服务边界和文本输入方式；长篇有声内容：优先验证分段一致性。** 目前的证据足以支持这一试用顺序，尚不足以断言它全面优于其他 TTS 模型。

与仓库已有资料衔接，可参考 [IndexTTS、Qwen3-TTS 与 VoxCPM2 对比调研](./2026-10-20-IndexTTS-Qwen3-TTS与VoxCPM2对比.md) 和 [VoiceStudio 项目调研](./2026-11-16-VoiceStudio项目.md)。两篇保留各自调研日期的结论；本文没有重新核查全部竞争模型。
