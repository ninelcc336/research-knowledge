# MiniMax 2.8 与 Qwen-Audio 3.1：中文声音克隆与口播视频选型

调研日期：**2026-11-16**。

适用需求：克隆本人音色，持续制作中文口播视频，偶尔包含英文产品名、技术词和缩写。优先考虑声音像本人、表达自然、发音可纠正、跨段可复用，以及修改一句台词的成本。

证据范围：重新在线读取两家官方指南、接口、价格及相关条款，并核查第三方听感偏好榜。本次没有用户录音、账号或 API Key，**未实际创建音色、未调用付费生成、未进行声音相似度或中文混读实测**。下文将官方支持、选型判断和待试听项分别说明。

## 1. 结论与试用顺序

**采用 API 制作口播时，建议先试 `qwen-audio-3.1-tts-plus`，再用 `speech-2.8-hd` 做同素材对照。** 千问 Plus 在复刻音色下的自然语言指令、SSML、读音修正和时间戳有明确支持，创建音色免费，中文合成单价较低；MiniMax HD 有额外短参考音频、发音词典、直接停顿标记和同步/异步字幕，适合作为高质量候选。[S1][S2][S3][S4][S5][S6][S7]

这调整了前面对 MiniMax 的优先建议：细查后，不能再把千问当作“便宜但控制弱”的备选。**两者谁更像你的声音，现有资料不能决定；首轮试用顺序也不等于最终音质排名。** 如果 MiniMax 明显更像本人或需要更少返工，个人口播用量下，多出的费用通常不足以否定它。

具体选择：

| 使用情况 | 建议 | 依据与边界 |
| --- | --- | --- |
| 可以使用 API，希望长期批量做中文口播 | **千问 3.1 Plus 首试** | 面向内容制作，控制能力明确、克隆免费、成本低；相似度需本人试听 |
| 千问声音不像本人，或语气总调不顺 | **MiniMax 2.8 HD 对照** | 可加入额外参考音频，声音效果可能更适合个人；不预设它一定更像 |
| 只想在现成网页上传声音、粘贴稿子 | **先看 MiniMax Audio 网页工作流** | 有创作产品入口；保存克隆、商用等权益与会员相关，不能套用 API 预算 |
| 已选定主力模型，只希望降低批量成本 | 再比较 MiniMax Turbo / 千问 Flash | 千问 Flash 改为 Token 计费，不能仅凭 Flash 名称保证更便宜 |
| 后续希望尝试 Google 的中文配音、双人对白或本人音色复刻 | Google AI Studio / Gemini TTS，**支付问题解决后再试** | 用户当前反馈境外支付方式绑定受阻；克隆明确要求付费层，详细补充见第 11 节 |

对这一需求，低首包延迟不是第一优先级，先比较 **Plus 与 HD** 更合适。官方分别把千问 Plus 放在有声书、影视配音、品牌声音与内容制作场景，把 Flash 放在低延迟交互场景；MiniMax 将 Turbo 定位为更快、更低成本。[S1][S6]

## 2. 先确认比较的是哪些产品

| 名称 | 本报告实际对象 | 不应混同的对象 |
| --- | --- | --- |
| MiniMax 2.8 | `speech-2.8-hd` / `speech-2.8-turbo`，以 MiniMax 国内开放平台原生 API 为主 | MiniMax 文本大模型；Audio 网页会员；海外美元价格 |
| 千问 Audio 3.1 | 百炼云端 `qwen-audio-3.1-tts-plus` / `qwen-audio-3.1-tts-flash` | 本地开放权重 Qwen3-TTS；旧 `qwen3-tts-flash`；实时语音对话模型 |

这里应使用“按给定文本合成”的 TTS。`qwen-audio-3.1-realtime-*` 是实时语音对话型号，`qwen-audio-3.1-tts-next` 是另一个声音生成入口，不是本次口播主方案。不能用这些相近名称的价格、参考音频限制或接口示例互相替代。[S1][S8]

**百炼也提供 `MiniMax/speech-2.8-hd` 和 `MiniMax/speech-2.8-turbo`。** 因而可以在一个云平台下比较两家，百炼当前列价同样是 HD 3.5 元/万字符、Turbo 2 元/万字符、复刻首用 9.9 元。但百炼代理入口和 MiniMax 原生接口不同；原生的全部参数、字幕、文件管理与音色 ID 不能默认跨平台通用。精细调优 MiniMax 时，本报告优先参考其原生 API。[S2][S3][S6]

## 3. 核心能力对比：均以自己的复刻音色为中心

| 维度 | MiniMax Speech 2.8 | Qwen-Audio 3.1 TTS | 对中文口播的影响 |
| --- | --- | --- | --- |
| 主要候选 | HD；Turbo 用于速度/费用对照 | Plus；Flash 用于低延迟/费用对照 | 先听 HD / Plus |
| 创建音色 | 上传音频取得 `file_id`，调用复刻接口，自定义 `voice_id` | `voice-enrollment` 创建，指定 `target_model`，返回音色 ID | 都无需自己训练模型 |
| 录音时长 | 10 秒至 5 分钟 | 推荐 10–20 秒，最长 60 秒 | 长度不是相似度的充分条件 |
| 额外参考 | 可选小于 8 秒音频及准确转写，用于提高相似度与稳定性 | 提供参考长度及预处理参数，未见同构的第二段 prompt 音频参数 | MiniMax 有一个值得实测的调优方向 |
| 主录音转写 | 主文件无必填完整转写；使用 `clone_prompt` 时短音频转写必填 | 当前创建接口无必填转写文本 | 不需先人工转写全部素材 |
| 中文与英文 | 支持中文、英文及 `auto` 语言增强 | 复刻音色支持中文、英文，可指定目标语言 | “两语种支持”不等于任何混读都正确 |
| 自然语言指令 | 本次原生 T2A HTTP schema 未见 `instruction` | 系统、复刻、设计音色均明确支持 `instruction` | 千问可以描述口播风格 |
| 情绪与语气事件 | `emotion` 枚举、`(breath)` 等语气事件；部分枚举有型号限制 | 自然语言指令、`[serious]` 等控制标签、`[sighing]` 等事件 | 应少量使用，避免演绎过度 |
| 发音纠正 | 发音词典、拼音、IPA、文本替换 | `hot_fix`；SSML 的拼音、英文 CMU 音标及替换 | 两者都能处理多音字/专名 |
| 停顿 | `<#0.3#>` 等，0.01–99.99 秒 | SSML `<break time="300ms"/>`；累计连续停顿最多 10 秒 | 都能配合剪辑节奏 |
| 字幕与对齐 | 句级/词级；非流式 JSON 字幕文件，流式返回字幕对象 | HTTP 字级时间戳仅流式输出可用，明确支持复刻音色 | 千问需要按流式接收以取得时间戳 |
| 同参数复现 | 当前 HTTP schema 未见 `seed` | 有 `seed`，官方声明同版本、同文本、同音色及同参数可复现 | 有利于保留某个满意版本，但不保证不同文本风格相同 |
| 长稿入口 | 同步及异步长文本；可用同一个复刻音色 ID | HTTP 一次提交文本，或 WebSocket 分段输入 | 都建议以段落作为可返工单位 |
| 音色生命周期 | 创建后 7 天未正式调用会删除；正式调用后可查询 | 默认长期有效，支持查询、更新、删除 | MiniMax 的 7 天不是“每周必须续用” |
| 模型绑定 | 复刻接口的 `model` 用于试听，未列出千问式 `target_model` 必填绑定 | 绑定 `target_model`，Plus 与 Flash 必须分别建音色 | 千问换型号时要重建，不可只改合成 model |

来源：[S2][S3][S4][S5][S7][S9][S10][S11][S12][S13]。能力矩阵表示文档支持范围，不是实测质量评分。

## 4. MiniMax 2.8：值得选它的原因与限制

### 4.1 复刻流程与录音要求

官方原生流程：[S3][S9][S10]

1. 完成个人或企业认证，准备开放平台 API Key。
2. 将主音频上传至文件接口，`purpose=voice_clone`，取得 `file_id`。
3. 可选：另传小于 8 秒的示例音频，`purpose=prompt_audio`，取得另一 `file_id`。
4. 调用 `/v1/voice_clone` 创建自己的 `voice_id`，可附 `text`、`model` 生成试听。
5. 选定后，7 天内正式合成一次，激活并保存 ID，后续合成复用该 ID。

主文件硬限制：MP3、M4A、WAV；**不少于 10 秒、不超过 5 分钟，不超过 20 MB**。可选短参考也是这三种格式，小于 8 秒、不超过 20 MB。`clone_prompt.prompt_text` 必须与短参考音频一致，句末有标点。[S3][S9][S10]

`need_noise_reduction` 与 `need_volume_normalization` 默认均为 false。干净录音先保持默认，不能把降噪开关当作必然提质。`text_validation` 是可选 ASR 文本校验，最长 200 字符，不是完整训练转写要求，也不是试听文案。[S3]

**文档的小瑕疵：** `file_id` 描述中有一句提到 `prompt_audio`、`prompt_text` 同时必填，结构上这两个字段属于可选的 `clone_prompt`；同页 `required` 列表只要求 `file_id` 和 `voice_id`。应据字段结构理解为“使用 clone_prompt 时两个子项一起提供”，不要误写成所有复刻都必须有第二段音频。[S3]

### 4.2 它的实际优势

- **可多一个相似度调优手段。** 官方明确说短参考音频有助于音色相似度与稳定性，适合主样本可用但细节还不像本人的情况。是否改善这位用户的声音仍要试听，不能解释为精确复制原录音情绪。
- **修正读音直接。** `pronunciation_dict.tone` 支持“原文/替换内容”，替换可以是汉字、拼音或 IPA；`<#x#>` 可直接标停顿，维护技术词口播词典比较方便。
- **字幕路径较完整。** 同步 HTTP 支持句级、词级与流式累计词级字幕；不做实时播放时可保存非流式音频和字幕 JSON，再转换为剪辑软件需要的格式。
- **有明确的异步长文批量入口。** 长稿可按文本文件或 zip 建任务，而不必将所有内容塞入一次同步请求。[S3][S5][S7]

### 4.3 它的不足与使用边界

- **每个正式使用的新复刻 ID 收 9.9 元。** 只用一个声音影响很小，反复创建并正式合成多个候选会累积费用；在复刻接口内生成试听则只按所选模型的合成字符收费。[S6]
- **自然语言风格控制不如千问接口直接。** 本次读取的原生 HTTP 参数没有通用 `instruction`。不能把“像朋友聊天，别像播新闻”这一整句直接当成 MiniMax 的已支持控制参数。
- **不能把全部 emotion 枚举都套给 2.8。** 同页明确写 2.8 HD/Turbo 不支持 `whisper`；`fluent`、`whisper` 的型号说明也有范围歧义。初始口播用自动情绪或文档较明确的 `calm`，不以 `fluent` 可用作选型依据。[S5]
- **长期存在不等于永久承诺。** 明确规则是“7 天未正式调用会删除”；管理接口说正式合成后才能查询。不能扩大成已激活音色永久不失效、永不收费。[S3][S12]
- **同一音色 ID 不保证每段语气完全一致。** 官方自己的复刻调优案例承认，同一原声音频的不同切片、prompt、复刻策略，会使候选在相似度、情绪和稳定性上不同。[S14]

**一个重要的费用矛盾：** 官方“音色复刻抽卡工具”案例一面称未激活候选无复刻费，一面描述候选创建后再调用 T2A 试听；价格页则明确首次正式 T2A 使用触发复刻费。本次未实测该工具的费用路径，因此不推荐依据该案例保证“6 个候选只付一次 9.9 元”。要低成本筛选，优先利用复刻接口内 `text` + `model` 的试听机制，再正式使用选中的 ID。[S3][S6][S14]

## 5. 千问 Audio 3.1：值得选它的原因与限制

### 5.1 复刻流程与录音要求

以北京地域 Plus 为例：[S2][S4]

1. 在百炼准备对应地域的 API Key 与业务空间 ID。
2. 请求音色定制接口，`model=voice-enrollment`、`action=create_voice`、`target_model=qwen-audio-3.1-tts-plus`。
3. HTTP 的 `audio` 可以是公网 URL 或本地音频的 Base64 Data URI；不必为了 HTTP 复刻额外搭公开文件服务器。
4. 保存返回 ID，并查询到 `status=OK` 后使用。
5. 使用同一个目标模型，将音色 ID 传入 TTS 的 `input.voice`。

录音要求：[S2]

| 项目 | 当前官方要求 |
| --- | --- |
| 格式 | WAV（16-bit）、MP3、M4A |
| 上传时长 | 推荐 10–20 秒，最长 60 秒 |
| 大小 | 不超过 10 MB |
| 采样率 | 至少 16 kHz |
| 声道 | 单/双声道；双声道只处理首声道 |
| 有效人声 | 至少 5 秒连续清晰朗读，其余仅允许不超过 2 秒的短暂停顿 |
| 内容质量 | 正常语速、无音乐、无其他人声、减少环境噪声和混响；不用唱歌录音 |

**上传时长与实际用于复刻的时长要分开。** `max_prompt_audio_length` 是预处理后用于复刻的参考音频最大时长，默认 10 秒，可设 3–30 秒。上传 60 秒并不意味着默认全部用于提取音色；文档也未保证一定采用文件最前面的 10 秒。可先用一段完整的 15–20 秒样本，并显式设置匹配的参考时长。[S4]

`enable_preprocess=false` 为默认；官方建议安静环境关闭以最大程度保留音色，有噪声再开启。`enable_volume_normalization` 在当前 HTTP 参考中是字符串 `"true"` / `"false"`，不要与布尔型 `enable_preprocess` 混写。[S4]

### 5.2 它的实际优势

- **自己的克隆音色也能听指令。** Plus、Flash 的系统、复刻和设计音色均支持 `instruction`，可以描述中文口播的语气、语速和表达方式；不是只有预置主播音色才能控制。[S7]
- **精细读法控制有明确入口。** `hot_fix` 能修正词语读音或替换文本；SSML 明确支持复刻音色，可以设置停顿、数字/日期读法、中文拼音、英文 CMU 音标和别名。[S4][S11]
- **创建音色免费，适合筛样本。** 可以比较两段录音、不同参考长度或预处理设置；实际试听合成仍按目标模型收费，并非所有步骤免费。[S2]
- **可保留生成种子。** 同版本、同文本、同音色和同参数下，官方声明相同 `seed` 可复现相同结果。建议保存每段的文本、参数与 seed，便于保留选中的表达。[S4]
- **维护音色更方便。** 默认长期有效，支持不变更音色 ID 而更新参考录音，也可查询绑定模型和删除；每账号复刻与设计共用 1000 个自定义音色配额。[S2]

### 5.3 它的不足与使用边界

- **Plus 与 Flash 的音色不能直接互用。** 相同原录音可以分别创建，但已有 Plus ID 不能只把合成型号改成 Flash；实时对话型号也一样受绑定限制。[S2][S4]
- **原生字级时间戳需要流式输出。** “离线做视频”仍可接收 SSE 流式结果并最终保存完整文件；离线业务不等于必须调用非流式接口。如果只请求非流式 URL，不能假设同时拿到时间戳。当前 HTTP 文本示例对时间戳载荷展示不充分，实际接入应核对流式事件。[S4]
- **SSML 不能随意双向分段发送。** HTTP 要 `enable_ssml=true`；WebSocket 的 SSML 模式只能发送一次 `continue-task`。不要把“支持流式”理解为所有输入语法都支持任意追加。[S11]
- **语言提示不是中英混读开关。** `language_hints` 虽是数组，当前只处理第一个元素，`["zh","en"]` 不能作为同时启用两语种的保证。[S4]
- **Flash 的成本不能按字符价猜。** 3.1 Flash 按输入、输出 Token 分别收费，输入文字长度相同也不能脱离输出用量给出确定单条费用。[S8]
- **指令控制仍不是精确剪辑约束。** “语速慢一点”“温和解释”不代表固定秒数、固定停顿或精确重音；要靠实际音轨再决定镜头和字幕。

另外，当前 HTTP 概述泛称支持 LaTeX，但专门的 SSML/LaTeX 使用限制只把 LaTeX 列给 CosyVoice。本需求无需公式朗读，因此不把千问 3.1 的 LaTeX 当作已验证优势。[S4][S11]

## 6. 中文为主、偶尔英文：两者该怎样使用

**不需要为了极少数英文单词，优先改用英语导向方案，也没有证据表明必须用双语录音才能克隆。** 两家都支持中文和英文，先保留中文自然口播的声音特征，再处理少量专名与缩写即可。[S1][S3][S5]

但要区分三件事：支持英语合成、保持本人声纹特征、把中文句中的英文自然读对。这三者不能从一个“支持多语言”标记中一起推出。

建议按以下顺序处理：

1. 先把中文段落和英文词一起原样合成，不拆成不同说话人、不先用汉字谐音。
2. 用同一声音分别试完整英文词（Windows、GitHub、Python）和逐字母缩写（API、GPU、JSON）。预先写清你希望的读法，例如 JSON 读英文单词还是逐字母。
3. MiniMax 从未指定语言或 `language_boost=auto` 开始，再对比 `Chinese`；不要认为 `auto` 保证正确。千问先自动识别，再比较只传 `zh` 的结果；不要误用双元素数组。
4. 对固定错读词建立词典：MiniMax 用 `pronunciation_dict`，千问用 `hot_fix` 或 SSML。英文音标两家语法不同，MiniMax 支持 IPA，千问该 SSML 文档列的是 CMU。
5. 特殊缩写仍不稳时，允许只改“实际朗读文本”，显示字幕继续保留标准拼写。发音替换可能改变时间戳对应文字，字幕需要校对。

可先用这一段检查：

```text
今天我们在 Windows 上，用 Python 连接这个 API。代码放在 GitHub，返回结果是 JSON。你不用一开始就买 GPU，先确认这条 workflow 真的能跑通。
```

## 7. 长稿、字幕与口播视频制作

### 7.1 长文本限制不能混算

MiniMax 当前同步 HTTP 写“文本小于 10000 字符，超过 3000 字符推荐流式”。本次异步接口已明确：直接 `text` 或单个 txt/zip 内文件最多 **10 万计费字符**，一个 zip 任务总计最多 **100 万计费字符**；这里汉字计 2。生成包含音频、句级字幕和附加信息，下载 URL 有效期 9 小时。[S5][S13]

这与仓库 2026-10-10 旧报告的“直接 text 最多 5 万、文件小于 100 万”不同。本篇按本次接口正文记录新边界，保留旧报告历史正文，不将 100 万解释为单个输入字段容量。

千问当前 WebSocket `continue-task` 文档列 **单次最多 20000 字符、累计最多 200000 字符、发送间隔不得超过 23 秒**。这些是该 WebSocket 事件的限制，不应直接套到 HTTP；本次读取的 HTTP `text` 参数未明确列长度上限，不能因此写成无限制。[S4][S15]

### 7.2 更适合个人口播的生产方法

建议每段约 **150–350 个汉字**，以语义完整的段落分割，保留同一个模型、音色 ID、语速和表达设置。这是便于改稿的工程建议，不是厂商规定的最佳长度。

1. 先把全稿中的数字、品牌名和英文词读法确定。
2. 分段合成，保存音频、原稿、实际朗读稿、模型参数和时间戳。
3. 通听开头、中段、结尾以及连接处，检查声线、气口、音量和语速是否突然变化。
4. 有一句读错，重做该段；相邻两段衔接不自然时一起重做，不能假设单句替换一定无缝。
5. 配音定稿后再排最终字幕、镜头和动画。时间戳可转为 SRT/ASS 或视频代码需要的结构，但需要实际转换与校对，不是 API 自带完整剪辑工程。

MiniMax 的 `subtitle_type=word` 表示词级，不应宣传为每个中文字都精确对齐。千问 `word_timestamp_enabled` 的文字说明为字级；实际中文标点、英文词和数字的边界仍要拿返回结果验证。若剪掉静音、变速或拼接，必须同步调整时间戳。

MiniMax 流式默认可能在末包返回聚合音频；不能把全部分片与最后完整音频再次拼在一起。可设置 `stream_options.exclude_aggregated_audio=true` 后自行拼片，或者使用末包完整音频。[S5]

### 7.3 输出格式与采样率

MiniMax 支持 MP3、WAV、PCM、FLAC、Opus 等，普通采样率选项最高列到 44.1 kHz；Opus 另有 48 kHz 的格式约束。千问 HTTP 支持 MP3、PCM、WAV、Opus，采样率包括 24、44.1、48 kHz。[S4][S5]

首轮统一用 **WAV / 24 kHz** 比较，避免 MP3 压缩和不同格式干扰听感。这是测试设置建议，不代表两家的模型内部音质相同，也不意味着设 48 kHz 会自动生成更多真实细节。成片需要 48 kHz 时再统一音轨规格。

## 10. 针对这位用户的最小对照方案

### 10.1 录音素材

建议录两到三遍正常口播，总素材可以较长，但**送给两家的公共对照片段选同一段 15–20 秒干净音频**：WAV 16-bit、单声道、24 kHz，无背景音乐、混响、其他人声或明显喷麦。不要用后期极重降噪、变调后的声音作为“自己的原声”。

先录中文即可；这是为了匹配主要内容，并非两家禁止英文样本。下面文案只是录音建议，按本人自然语速裁出完整一段，不要求机械卡秒：

```text
今天我想分享一个自己反复试过的方法。刚开始的时候，我也觉得它有点复杂，但把过程拆开以后，你会发现真正需要注意的地方并不多。接下来，我用一个具体例子，把每一步讲清楚。
```

MiniMax 再另备一段 **5–7 秒**的自然短句，提供准确转写，用来比较加/不加 `clone_prompt` 的差异。千问可比较参考上限 10 秒与 20 秒；每次只改一个条件，不要同时换录音、语速和情绪后再声称某个参数有效。

### 10.3 验收内容与选择规则

每家先生成同一套共约 1000 汉字的稿子，包括普通介绍、解释转折、数字、多音字、中英混读及一段较长结尾。各生成三次：第一次默认表达，第二次只调整表达控制，第三次验证满意设置能否稳定复用。千问同 seed 用于复现时另行标记，不能当三次独立随机样本。

| 检查项 | 通过标准 | 在选型中的作用 |
| --- | --- | --- |
| 声音像本人 | 本人及熟悉你的人听完，能认出主要声线和说话质感 | **第一优先**；“更像专业主播”不能替代 |
| 自然度 | 中文连续听 1–2 分钟，无反复机械断句或不合时宜重音 | 与相似度一起决定主力 |
| 内容准确 | 无漏词、重复；数字、英文和多音字经修正后正确 | 错误频率影响返工 |
| 中英衔接 | 英文词清楚，前后声线与音量不突变 | 对这个场景必须通过 |
| 跨段表现 | 首、中、尾与连接处听感一致，不突然换成另一种播报腔 | 防止短样本好听但长稿难用 |
| 可维护性 | 改一句后能局部重做，时间戳可整理为字幕 | 决定持续视频制作效率 |
| 总成本 | 统计满意版本的生成次数与实际费用 | 不只比较第一次成功请求的价格 |

**最终决策规则：** 两者都满足相似度与发音要求时，优先千问 Plus；MiniMax HD 明显更像本人或返工少时，选 HD。选定后再验证 Turbo/Flash 是否能保持可接受的效果。保留原录音和完整参数，避免将来升级模型时只能重新猜设置。

仅按两家各 3000 纯汉字合成、MiniMax 正式使用一个新 ID 估算，对照基础费用约为 **¥12.84**（千问 ¥0.84 + MiniMax HD ¥2.10 + 复刻 ¥9.90），不含标点、额外试听和其它候选 ID 的首用费；这是预算计算，没有实际消费。

- 中文声明已有支持，原文为：“我是此声音的拥有者并授权谷歌使用此声音创建语音合成模型”。它是该产品创建流程的一部分。
- 默认保存模式返回 `voice_...` ID，项目下设计/复刻共最多 200 个，**最后使用后保存一年，每次使用重置期限**；另有 `store=False` 的 `voicekey_...`，有效期固定 7 天。

当前文档将预置音色双人生成与自定义声音分开：**两个复刻音色的对白须逐角色生成后拼接**。因此，若以后做“自己的声音 + 另一角色”的视频，制作步骤会比单人旁白多。[S20]
